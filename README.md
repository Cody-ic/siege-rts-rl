# siege-rts-rl

## 下载游玩

前往 [GitHub Releases](https://github.com/Cody-ic/siege-rts-rl/releases/latest)，下载
`Sanctum-1.0.1-Windows-x64.zip`，选择“全部解压”，双击 **圣城.exe**。
玩家无需下载 Source code、安装 Python 或编译工程。支持 Windows 10/11 x64，
需要 OpenGL 3.3 显卡驱动。仓库仍为私有时，下载需要项目访问权限。

主菜单点击“攻方策略”可切换脚本 / RL，发布包内置项目当前选定的训练成果。
每次启动默认脚本；切换前自动保存，两种策略分别继续自己的存档。
RL 控制模型支持的兵种与等级，其余单位保留脚本行为，无需安装 Python 或训练。
新开局重置剧情，继续存档恢复本局进度。正式版存档 v6 与此前分支版本不兼容，
旧文件会保留备份，请使用对应旧版继续旧局。打包说明见 [tools/release](tools/release/README.md)。

C++ 程序设计课程设计。**不对称波次生存 RTS**：玩家守城（建墙、造防御建筑、经营经济、
指挥部队），进攻方由**强化学习**驱动，一波一波来袭，无尽模式。

形态接近 *They Are Billions*，差异化卖点是**攻方由 RL 驱动而非脚本** ——
它会侦查、会佯攻、会挑你防线的薄弱段打，也会读你的防空布局决定要不要派空军。

> **本文只做导航与协作约定，不放设计决策。**
> 设计决策全部在 `CLAUDE.md`，那是唯一的设计契约。本文若和它冲突，以 `CLAUDE.md` 为准。
> 这条是刻意的：本项目吃过"同一件事写在两处、然后漂移"的亏。

`deferred_command_count()` 那个记账口按当初的约定已删；**冲锋与齐射**（第四批）
——冲锋动量逐 tick 累距（站停/撞停归零、前摇冻结、落地耗尽），
「伤害 ∝ 助跑距离」机制等级无关；克制倍率**由三轴推导不平铺 N×N**（唯一的
数值克制关系：`Melee × HeavySlow` 打有动量的 `Charge`，幅度随对方动量线性
放大，「开阔地克、巷战被反克」因此不需要读地形）；`Tower` 齐射（建筑 AOE，

**在途弹丸**（第五批，第四组实体）——谁放弹丸是结构（单位侧 Ranged × 非空中
= `Archer`/`Shade`，建筑侧凡开火皆弹丸 = `Tower`/`Flak`；`Ram` 前摇撞击、
`Phoenix` 俯冲直击），单体弹丸追踪目标句柄、齐射弹雨飞向锁定落点
（散开的躲闪窗口 = 前摇 + 飞行），高度 miss / 减伤在**命中那一刻**按目标

——field 是 `WorldView` 之上的**纯函数**（`rts/flow.hpp`，不进世界状态、

## 三条不变量

`CLAUDE.md` 里绝大多数内容是**有理由的工程选择**，理由不成立了就可以重开讨论。
**真正不可动摇的只有三条**，它们保护的是训练吞吐量与可复现性：

1. **仿真 tick 的热路径内不得出现渲染器、引擎、或向上回调 Python。**
   Python 一次调用推进 N 个 tick，绝不能每单位每 tick 回调一次上层。
   `rts_core` 必须能在完全 headless 下跑完整局。
2. **渲染层是 `rts_core` 的只读观察者。** 渲染代码不得修改仿真状态；
   训练时 `render/` 整个不参与编译链接。
3. **训练回路里没有渲染器、没有引擎。** Python 经 pybind11 **in-process** 直接调 C++，
   不走 IPC、不做状态序列化。

其余的（不用游戏引擎、用 raylib、扁平数组、五种地形……）都附了理由与重新评估的判据。

## 协作约定

### 分支与 PR

```bash
git checkout -b <类型>/<简短描述>     # docs/ design/ tools/ feat/ fix/
# ... 改动 ...
git commit                            # 提交信息见下
git push -u origin <分支名>
gh pr create --base main
```

不直接推 `main`。PR 描述要写清**为什么这么改**，不只是改了什么 ——
四个人都在用 Claude Code，读 PR 是同步认知最有效的途径。

### 提交信息

**写"为什么"，不只写"是什么"。** 标题一行，空行，正文说清动机与取舍。
本仓库现有的提交可以直接当模板抄。

### 每个人推自己的提交

`git log` 是答辩「人员分工」页的证据，而那页是**个人成绩的重要依据**。
不要代替别人提交。git 身份用 `--local` 配，不要动全局配置：

```bash
git config --local user.name  "<你的 GitHub 用户名>"
git config --local user.email "<你的 GitHub noreply 邮箱>"
```

### 日志纪律

**每次上机后当场补录 `日志.md` 自己那一行。**
`git log` 能补齐"改了什么"，但补不齐时间线、讨论结论与个人分工 —— 这三样只能人工记，
而且事后回忆一定会漏。这份日志要转成 `.doc` 交付，同时是答辩人员分工页的直接依据。

### 不要提交这些

`.gitignore` 已覆盖构建产物、训练权重、`__pycache__` 等。
另外**个人的 `.claude/` 目录不要提交** —— 它是每个人自己的配置，不该进团队仓库。
用 `.git/info/exclude` 排除（这个文件不入库，只对你本地生效）：

```bash
echo ".claude/" >> .git/info/exclude
```

## 本地环境

**全员 Windows + MSVC，不使用 WSL2。** Linux 只存在于训练用的 GPU 服务器上。

| 需要什么 | 说明 |
|---|---|
| Visual Studio 2022 | 自带 MSVC 与 CMake，够用，不必单独装 |
| Python 3.10+ | 跑 `tools/`。目前只有精灵流水线用到，只依赖 Pillow |
| Blender | **可选**。只有要重新渲染精灵时才需要 —— 成品已入库，前端可直接用 |
| GPU 服务器账号 | 训练用。配置、环境、连法与已知的坑见 **`训练服务器环境.md`**。**要尽早、频繁地在服务器上跑构建**，见下 |

克隆体积约 135 MB（`.git` 77 MB + 工作区 59 MB，其中 CC0 模型 42 MB、精灵成品 17 MB）。
素材必须入库：交付清单要求「软件源代码**包括输入文件和输出文件**」。

**关于跨工具链**：本地 MSVC、服务器 GCC。MSVC 是三大编译器里与标准分歧最多的一个，
GCC 侧的编译问题只有推到服务器才会暴露。**不要攒到临近答辩才第一次编译 Linux 目标。**
CMake 要同时支持两条路径，MSVC 侧开 `/permissive-` 与 `/Zc:__cplusplus`。

### GCC 那一轮谁跑：**有兜底，不靠「下次上机记得」**

`ssh gpu` 要在校园网内。**这不是每个人每时每刻都成立**，而它已经造成过两次积压：
#74 与 #57 各标了一次「⚠️ 服务器侧还没跑」，第二次时已经欠了五个 PR。

`-Werror=dangling-reference`），合并的时候没有任何人知道。

所以约定成两条，而不是一句「每个人都该跑」：

1. **能连的时候自己跑**，两分钟：
   `tools/server/sync.sh && ssh gpu 'cd $HOME/Cody-ic/siege-rts-rl && tools/server/build.sh Release'`
2. **连不上就在 PR 或 #57 里说一句**，@Cody-ic 补跑。不要写「下次上机第一件事」——
   那句话到目前为止兑现率是 0，两次都是别人补的

**这不改变「每个人都该会跑」**，只是给它加一个不依赖某个人网络状况的兜底。
判据很简单：**动了 `rts_core/` / `game/` / `tests/` / CMake 就该跑一轮**；
只动 `render/`、文档的不必（`render/` 在训练构建里根本不配置，
所以它**永远**只有 MSVC 一套工具链把关——那条代价见 `训练服务器环境.md`）。

> **补一条判据：新增 ctest 条目的 PR 也该跑一轮，无论它动的是哪个目录。**
>
> 上面那条按「动了哪个目录」划，而 #77 是个反例：它**只动 `tools/`（纯 Python）
> 与 `tests/CMakeLists.txt`**，C++ 一行没改，按目录判该归入「不必」——
> 但它新增的两条 ctest 条目会**在那台机器上真的执行**，而 Python 侧的版本、
> 默认编码、路径行为都可能不同。本仓库在这上面已经踩过两次
> （cp936 编码不了 `✓`、中文路径打不开文件），两次都是「同一份代码在两台机器上
> 行为不同」。
>
> 所以判据是**两条的并集**：动了那四处 **或者** 新增/改了 ctest 条目。
> 原来那句「只动 `tools/` 的不必」因此收窄了——`tools/` 里的东西一旦被注册成
> ctest 条目，它就不再只是本机脚本了。

**报告时带上口径。** 服务器是 `RTS_BUILD_RENDER=OFF`，所以它的「全绿」比本机少
那几条 `render_*`。写成 **「GCC/`RENDER=OFF`：<通过>/<总数>」** 而不是
「全绿」——同一个数字在两台机器上指的是不同的集合，而看报告的人只会记住数字。

**这里刻意不写具体数字当例子。** 原文举的例子是「32/32」，而它在写下后的
一小时内就过期了（#77 加了两条条目）—— 同 `CLAUDE.md`「条目数不写死，要数就
`ctest -N`」那条纪律。**要对照两台机器的差集，就两边各跑一次 `ctest -N`。**

> **这一轮补不上：#91 那两类 MSVC 一个都抓不住（实测过，不是推测）。**
>
> | #91 的那一类 | MSVC 侧 |
> |---|---|
> | `//` 注释里的行尾反斜杠 | `/w14010`（single-line comment contains line-continuation）**对那个形状不报**：`-W4 -w14010 -WX` 编那段样例退出码 0 |
> | `uint64_t` 与 `...ull` 混算 | **在 MSVC 上根本不存在**——Windows 是 LLP64，`uint64_t` 本来就是 `unsigned long long`，没有类型分歧可报 |
>
> 也就是说这两类**结构上**只有 GCC 看得见，本地纪律与编译器开关都补不上，
> 而这条约定（外加 `-Werror`）是目前唯一的守卫。**它已经漏过两次**（#63、#91），
> 两次都是 `main` 在服务器侧编不过、合并时无人知道。
>
> **候选的第三条路是让机器跑那一轮**：`.github/workflows` 加一个 `ubuntu-latest`
> 的 `RENDER=OFF` 构建 + `ctest`，PR 上自动红。它不占任何人的时间、也不依赖
> 谁的网络状况，符合本仓库「结构封死，而非靠纪律劝退」的一贯做法。
> **尚未表决**（题面在 #57 与 #93 的评论里），所以先记在这里而不是直接加。

构建命令：

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build -C Release
```

**PATH 里通常没有 cmake。** VS2022 自带一份，不必单独安装 —— 两种用法：

- **在 VS 里**：「打开本地文件夹」选仓库根目录，VS 会自动识别 `CMakeLists.txt`
- **在命令行里**（Git Bash / PowerShell）用完整路径：

```bash
CM="/c/Program Files/Microsoft Visual Studio/2022/Community/Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin/cmake.exe"
"$CM" -G "Visual Studio 17 2022" -A x64 -B build
"$CM" --build build --config Release
```

**VS 18（2026）同样可用**（已实测，Release/Debug 双配置零警告、ctest 全绿）：
路径里的 `2022/Community` 换成 `18/Community`，生成器用 `-G "Visual Studio 18 2026"`。

> **上面那条路径只对「VS 完整版装在 C 盘默认位置」成立，而组里至少有一台不是。**
> 一台机器上装的是 **Build Tools**（不含 IDE）且在 D 盘，于是路径是
> `D:/tools/BuildTools/Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin/cmake.exe`
> ——`/c/Program Files/Microsoft Visual Studio/` 整个目录不存在。
>
> **不要照抄路径去猜，问构建目录**：`CMakeCache.txt` 里记着当初用的那一份，
> 一行就能查出来（顺带查出生成器是 VS 还是 Ninja，那决定要不要 `--config`）：
>
> ```bash
> grep -E "^CMAKE_COMMAND|^CMAKE_GENERATOR:" build/CMakeCache.txt
> ```
>
> **另外 Git Bash 里直接 `cmake --build` 会失败**，报 `fatal error C1083:
> 无法打开包括文件: "array"` 一类——那不是代码问题，是 `INCLUDE` / `LIB`
> 没设（构建目录当初是从 Developer Prompt 配的）。两种解法：在 Developer
> Command Prompt 里构建，或者把 vcvars 的环境导进当前 shell：
>
> ```bash
> cmd //c 'call "D:\tools\BuildTools\VC\Auxiliary\Build\vcvars64.bat" >nul 2>&1 && set' > /tmp/vcenv.txt
> export INCLUDE="$(grep '^INCLUDE=' /tmp/vcenv.txt | sed 's/^INCLUDE=//')"
> export LIB="$(grep '^LIB=' /tmp/vcenv.txt | sed 's/^LIB=//')"
> ```

首次配置会经 FetchContent 下载 Catch2（约 1 MB，**需要联网**）；之后可加
`-DFETCHCONTENT_FULLY_DISCONNECTED=ON` 离线复用。

挑单条用例跑（ctest 条目按标签划分，用例名本身是中文、不适合当命令行过滤器）：

```bash
ctest --test-dir build -C Release -R rts_tests_rng    # 按标签
./build/tests/Release/rts_tests.exe "<用例名>"         # 按用例名
```

几个构建开关：`-DRTS_BUILD_TESTS=OFF`（不建测试）、`-DRTS_BUILD_RENDER=ON`（建前端，
**目前 `render/` 还不存在**）、`-DRTS_WARNINGS_AS_ERRORS=OFF`（警告不当错误，默认当）、
`-DRTS_REQUIRE_DETERMINISM_GUARD=OFF`（**只在机器上确实没有 Python 时才用**：
默认情况下找不到 Python3 会让配置直接失败，因为确定性守卫是一条 ctest，
静默摘掉它的话 ctest 少两条、照样全绿，没有任何东西提示守卫没了）。

**性能相关的改动一律在 Release 下测量**，Debug 构建的仿真吞吐不具参考意义。
