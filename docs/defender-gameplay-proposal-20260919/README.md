# 守方体验、城外战术与剧情改进提案

日期：2026-09-19。状态：待实施、非紧急。本文整理 v1.0.1 试玩反馈、源码核验和后续讨论，不代表功能已实现或数值已定案。

规则基线为 `fb0c36d6f121d24521a618c801393f17ad71f748`；对局使用脚本攻方。既有第41—91波证据和发行版截图见[核验记录](evidence.md)，完整通关与续局复盘见 [PR #197](https://github.com/Cody-ic/siege-rts-rl/pull/197)。本提案可独立评审，不要求先合并 #197。

## 1. 问题与本轮边界

原设计要求通过侦查、外围资源争夺、机动部队和攻方应对形成战术选择。当前玩家的地面调遣到达后即失效，部队恢复以堡垒为中心的默认行为，难以长期守矿、护卫工匠或充当侧翼预备队。建筑可以持续落实玩家布局，部队却难以持续落实玩家部署。

因此，少用士兵、多用工匠不能直接归因于玩家配置失衡。工匠能持续维持塔阵，部分部队则受到建筑友伤、任务失效和残血退守的影响。先恢复有用的作战选择，再判断强度和人口是否需要调整。

| 项目 | 本轮方向 | 尚未确定 |
|---|---|---|
| 工匠 | 继续占普通人口，与士兵共同竞争名额；不新增工匠比例上限，不另设工程配额 | 部队修复后是否仍需放宽总人口 |
| 斥候 | 建议不占普通人口，并缩短有效情报的等待时间；保留金币、训练时间与侦查风险 | 速度定值、大量招募的收益与是否需要其他约束 |
| 猎骑及部队 | 先补持久部署、有限追击、支援与撤回，解决城外任务缺失 | 风险判据、恢复费用和速度、界面细节 |
| 建筑友伤 | 支持取消守方建筑对友军的溅射，验证与近战部队的协同收益 | 联合平衡后的数值 |
| 《一跃》 | 建议按同一身份跨波累计实际交战，击落不清零；仍在第60波后开放阅读 | 累计次数、接战事件定义、正常对局触发分布 |
| 彩蛋提示 | 沿用现有日记线索与“触发彩蛋”通知，不新增战后记录、线索短文或拾取任务 | 无新增提示需求 |
| 《微笑者》 | 保留审阅正文，改善排版；游戏只显示本局选择对应的结尾 | 放下武器路线的解锁入口属于待评审建议 |

前期讨论过的斥候速度 `0.14/0.145/0.16—0.18`、白羽“三次交战”均未定案，不作为默认实现值。普通玩家没有工匠30%硬上限；现有 `noncombat_max_permille` 只作用于自动守方招募脚本，不能把它扩成玩家规则。

## 2. 先补持久部署，建立城外争夺

### 当前缺口

- 地面移动到达后清除临时指令，默认驻防点回到堡垒附近，缺少“长期守住此处”的任务。
- 猎骑自动选敌主要局限于城墙外接矩形内部且距堡垒8格以内；外接矩形不代表真实的保护范围。
- 自动撤退参考近处骑士、人数比及40%血量阈值。手动移动分支在这些判断之前；空闲清障也没有路线风险检查。
- 当前寻路主要比较通行耗时，不能充分表达接近目标和撤回时的受击风险。上述缺口提供了送死路径，但不能据此断定玩家某次阵亡的唯一原因。
- 攻方已有基于侦察记忆的编成调整、经济袭击和寻路，然而脚本主攻方向按波次轮换，分兵比例固定，没有形成完整的“部署—应对—再部署”过程。

### 第一阶段：玩家任务持续有效

1. **驻防区域：** 单位记住岗位与活动范围，在范围内接敌，限制追击，战后回岗；跨波和读档保持，直到玩家换令、取消或单位死亡。
2. **护卫任务：** 指定矿场、施工点或工匠，围绕任务对象提供掩护。对象失效时明确结束任务或返回指定驻地，不能因为身份槽位复用而护卫了另一个实体。
3. **撤回任务：** 保留明确撤回点，综合可通行路径与可见威胁选择路线；不能一律直奔堡垒而穿过敌群。
4. **命令优先级：** 玩家持续任务高于自动清障和默认回家。普通调遣保留避险；强攻如需支持，应成为玩家能明确辨认的指令。新兵是否继承岗位由显式集结设置决定，不能暗中接管旧单位任务。
5. **可见状态：** 显示岗位、护卫对象、追击范围和撤回原因。任务失败或路线不可达要有反馈，避免单位沉默停住或不断尝试穿墙。

单位仍自主完成走位、接敌和回岗；玩家主要决定守哪里、保护谁、是否出击。任务记录须接入保存和回放，更改行为时按仓库兼容约定迁移或升级存档版本。

### 第二阶段：让兵种各有可执行任务

- **枪卫：** 守入口和通路，掩护弓手与工程，不被敌人轻易引离防区。
- **弓手：** 在指定防区提供火力和利用驻墙条件，不因全图寻找空墙而擅自离岗。
- **猎骑：** 支援外围防线、护卫扩建、截击暴露的法师或攻城锤；城内空间有限时不要求它强行承担所有近战任务。
- **工匠：** 保留施工、维修与人口规则。护卫存在不能被当作自动安全许可，仍需检查实际威胁和退路。

猎骑不能只加回血或放大追击半径。出击前需要考虑目标附近敌军、实际兵力与等级、有效友军支援、接近和返程路径；交战中持续重估。脱战恢复可以进入候选方案，但费用、时间和触发方式须另行验证，不能把无限拉扯回血当成既定收益。

### 第三阶段：补攻方应对

攻方根据真实获得的情报，在突破、袭矿、牵制间选择；守方调兵后，应有利用另一处空缺的机会。目标选择需比较收益、接近代价与交战代价，包含以下既有问题：

- 防空数量或覆盖比例不足以判断不死鸟是否值得出击，还需比较具体防空的等级、火力和能否先行摧毁。
- 绕墙耗时与受击风险可能高于直接破墙，不能只找当前最低通行耗时。
- 后期塔阵和生产建筑具有战略价值，不能始终只在挡路时拆除。
- 固定集结区、外围资源和扩张边界需与前线外移一起评估，见 #197。

这些基本决策可先用可解释的脚本验证，再供 RL 学习或替换。训练成功不能替代玩家指令缺失，也不能作为迟迟不补玩法的前置条件。

### 最小玩法验收

选择一处未被城墙圈入的外围采石场：派枪卫、弓手驻防，工匠施工，猎骑待命。至少跨过多个波次，并验证：

1. 队伍接令后确实留下，交战后回岗，清障与换波不会覆盖任务，读档后部署相同。
2. 侦查到强攻时，玩家可以增援、集中截击或主动撤离，部队能够落实选择。
3. 猎骑能抓住暴露目标的机会并撤回，不因远处可见目标无限追击；危险过高时不出击也必须有合理理由。
4. 对手对不同部署产生符合情报条件的应对。比较“守矿、增援、放弃”在资源保有、部队损失和主城风险上的差异，不要求驻矿必胜。

验收重点是选择能否稳定执行并改变局面，不能只统计猎骑伤害、存活时间或工匠比例。

## 3. 斥候：人口与速度围绕情报用途评估

发行版斥候速度为0.13格/tick（20Hz下2.6格/秒），一级25金币、60tick训练，视野10格。默认进入集结点的10格切比雪夫范围、周围存在攻方单位后，按固定40%概率直接判定阵亡；途中仍可能受到真实攻击。

这个抽签与骑士速度无关。“必须比骑士慢”不能作为当前调速的硬上限。提高速度会影响实际接敌，但应单独测量，不把旧版降速注释当作效果证据。

此前口头使用的19—21秒来自“走到集结点中心”的距离估计，不是当前到达判据下的跨地图实测。需要重新测量从出兵到取得有效报告的时间，纳入训练、绕路、探空集结点和换路；不能据此直接锁定速度。

建议：

- 斥候及其在训占位不计普通人口，满人口时仍可训练；工匠保持现行人口成本。UI、模拟校验、自动守方和训练动作掩码必须一致。
- 先保留金币、训练槽与失败风险；不预设新的数量上限，评估大量斥候是否带来持续全图可见或引敌等额外收益。
- 调速目标是及时取得情报并留出调整部署的时间。分别比较原值、仅提速、仅人口豁免及两者组合，避免把两项效果混为一谈。
- 报告必须标明侦查路线与时刻。当前 `scout_report_` 在下一名斥候成功时清空重写，只有一份报告；需要评估多路线报告的保留方式，不能把后来的局部情报误当作完整编成。

记录首次有效报告时刻、进攻开始前的剩余时间、真实拦截与随机失败、玩家实际改令及其结果。如果情报到手仍没有值得执行的操作，仅提速不能解决侦查价值不足。

## 4. 人口、友伤与建筑升级

### 人口与友伤

工匠继续占普通人口，不增加比例限制或单独工匠配额。终点31工匠/66人口是该局的选择结果，不能仅凭47%就认定过多。先比较新增一名工匠或士兵对防线、损失和经济的实际贡献；自动守方的招募偏好与玩家规则分开管理。

支持取消守方建筑投射物对友军的溅射，保持敌军受伤规则，避免附带改变全部单位伤害。当前自主作战很难稳定规避自家齐射，且已出现大量枪卫被自家箭楼击杀。修复后要验证近战、骑兵、工匠与塔阵的联合收益，再决定总人口是否需要放宽。

### 城墙与批量操作

后期低级墙升级常跨不过多扛一次攻击的门槛；高等级也并非线性划算。按单锤、多锤、混合兵力、驻墙高度和快速补墙/抢修共同评估成本与收益，不只比较满血数值。证据中的静态计算不等于实战结论。

建筑操作需要明确的批量管理模式、类型过滤、相连墙线选择、费用预览和排队/取消反馈。避免墙头单位抢走建筑框选，也避免默默选中全图建筑。

新建建筑可以预设目标等级，由系统自动接续施工和升级，保留累计资源、工时与等级上限。若允许直接高等级成型，还需另验工地血量、开火时点和取消退款；省点击不应默默省掉工匠工作。

### 兵营与资源建筑

当前兵营升级只增加血量，训练速度、并行数、征兵等级上限和人口均不随兵营等级增加。地面脚本没有专门选择兵营的决策，通常只有兵营挡住选定路径且拆除比绕行便宜时才自动拆它；抢资源时通用建筑选目标与攻城锤范围伤害也可能顺带波及。第41—91波兵营没有承伤或攻击前摇目标记录，耐久升级在这局没有兑现收益。

兵营升级应有与军事生产相关的价值，可试验有限、逐渐减弱的训练提速，与另建兵营的并行产能形成选择。人口扩容属于另一个候选，不把多项增益一次叠满，也不增加“升堡垒后再逐座升兵营才能招高级兵”的重复门槛。

资源建筑升级同样只加血，不加产量；会受袭不代表加血一定划算。应验证它是否跨过攻击次数门槛、争取抢修时间或减少断供，不能为了形式统一直接加产量，进一步放大工程经济。

## 5. 彩蛋、结局与发行体验

### 《一跃》触发

现规则要求同一只不死鸟累计10次无阵亡成功撤离，被击落后计数清零。这与正常防空冲突，也受派出身份和敌方撤退行为影响。

建议同一身份在不同波次实际交战时累计，撤退或被击落都保留已发生的经历，重生继续计数；仅在集结点出现、没有接战就离场不算。每身份每波最多一次，不把不同鸟合并计数。具体次数以及“交战”以攻击承诺、命中还是其他可观测事件判定，均待验证；不预先绑定未完成的侦查系统。

保留第60波的阅读门槛、现有日记线索和“触发彩蛋”通知。无需新增战后记录、重复提示短文或冒险拾取任务。读档不重复累计，新局清空；普通防守、强防空、偏地面及不同地图都要核验可达性。

### 《微笑者》入口与分支

守护路线第90波通过损失清单解锁的安排具有叙事意义，建议保留。放下武器路线可在结局演出后开放人物小传，作为另一条入口；这是待评审提案，不宣称已获最终定案。

正文前七节共用，第八节只显示本局选择对应的结尾。主线结局按钮也应受同一访问规则控制；不能只隐藏按钮而仍能直达未选分支。审阅正文不在本提案中改写或压缩。

### 呈现与发行边界

- 第70波使用独立抉择呈现和简短世界回应，清楚说明继续对局或结束本局；记录选择后再转场，允许跳过，不用界面提前评价选择，也不为演出伪造真实仿真伤亡。
- 小传改善篇名、小标题、正文层级及行宽，提供长文导航与阅读位置记忆。关键句按既定要求强调；文字内容另行审阅。
- 普通发行包关闭开发者热键、调波及剧情预览入口；独立内部构建保留验收工具。Release编译优化本身不等于关闭开发者模式。
- 日记和彩蛋继续属于本局，新局不继承，读档恢复本局进度；预览不写正式进度。

## 6. 分项实施与验收

本提案暂存后续排期，不启动长训练、部署或游戏规则改动。后续建议拆成可独立评审的变更：

1. 持久驻防、护卫、撤回及存档/回放支持，先跑通外围采石场场景；同步处理建筑友伤与任务被默认行为覆盖的问题。
2. 猎骑出击风险、撤回和再次投入机制，与枪卫、弓手协同；记录实际任务完成情况。
3. 斥候人口豁免、速度与报告可用性，分别验证成本和情报转化。
4. 攻方突破、袭矿、牵制与目标收益；与守方改动做旧双方、只改攻方、只改守方、双方都改四组比较。
5. 建筑批量管理、目标等级计划、墙与兵营升级收益，分别评估操作收益和数值收益。
6. 剧情访问、彩蛋条件、阅读排版与发行工具隔离，单独验收。

单波固定输入仅用于定位；多波比较必须允许玩家/守方策略快速补墙、增援、撤离和重新分配资源。覆盖早期、40—60波、80—90波与不同地图，不能把固定旧操作在新规则下的结果当作最终平衡结论。

持久任务覆盖换波、读档、目标死亡、单位身份复用、不可达和手动换令。建筑计划核对资源与工时等价。剧情覆盖两种选择、未选分支、退出重进、新局和内部预览，并检查常见窗口尺寸。

## 7. 证据边界

本次完成的是源码核验、既有对局数据整理和发行版截图检查。没有执行新规则对照，也没有证明某一斥候速度、交战次数、恢复方式或兵营收益已经配平。合并本文仅归档问题、方向和验收要求，不表示相关功能完成。
