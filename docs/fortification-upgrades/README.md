# 墙类升级：分段耐久与价格封顶

城墙升级的新增血量越来越少，费用却持续上涨；批量操作只能缓解点击负担。此次候选针对城墙、城门、木栅栏调整升级收益，并为无尽后期限制耐久和价格的增长。单位、箭塔及其他建筑沿用原曲线。

## 规则

- 1～20级：每升一级增加基础血量的10%，不复利。
- 20级以后：保留已获得的血量，重新开始根号增长；20→21级的增量仍为基础血量的10%。以城墙为例，连续增量为120、109、102、96……整数开方和舍入可能造成后续增量有1～2点的上下变化，总体递减。
- 升到20级前：保留现有工料下限，升级标度从40%起、每级增加10个百分点。
- 升到21～30级：每级涨幅减为5个百分点。这里是相对于建筑升级标度的百分点，并非上一笔费用乘1.05。
- 30级以后：每次升级固定收取29→30级的价格。城墙81石＋27木，城门54石＋81木，木栅栏0石＋40木。等级和累计花费仍可继续增长。

城墙单次升级价格从19→20级的66石＋22木，过渡到20→21级的67石＋22木；小额资源逐项向下取整。首级基础血量、堡垒解锁、工匠工时、升级保持血量比例、升级与维修互斥等规则保留。Alt框选墙类、U批量升一级，共用单座升级的报价和结算。

## 公式及参数

令基础血量为H、线性步长a=0.1、转折等级T=20：

```text
L <= T: H × [1 + a × (L−1)]
L > T:  H × [1 + a × (T−1) + √(1 + (2a+a²) × (L−T)) − 1]
```

根号内系数为0.21，第一步满足√1.21−1=0.1，因此不会出现125血的突起。C++用整数千分比及整数平方根确定性计算，最后按引擎规则舍入；不会反复乘当前血量。

数值表的四个全局参数为 `fortification_hp_permille_per_level=100`、`fortification_linear_until_level=20`、`fortification_price_step_permille=50`、`fortification_price_cap_level=30`。所有字段参与指纹，载入时拒绝缺失或非法值。
