# 攻方奖励配方：旧对照与 attrition-v1 候选

2026-09-14；基于 #183。#180 是审计，不是已实现的新奖励。这次把新候选实际接入 PPO，同时完整保留修正误伤后的旧配方。它是可训练、可消融的第一版，不是经实验认定的最优数值，也不代表连续波次目标已实现。

## 事实记账与价值选择分离

原生 tally 保留原 15 列，并追加 11 种兵种的敌军击杀等级和、己方战斗阵亡等级和，以及被摧毁非堡垒建筑的石、木重建报价和当时有效的单周期石/木/金产出。

伤害结算只记一次实际击杀，误伤不产生敌军收益，但己方死亡仍计损失。运行时移除单位不算战斗死亡。已完成升级按当前报价逐级累计；未完成升级的预付费用尚未计入，因此这是重建报价而非历史实际投资。初始赠送建筑也按重建价计；玩家拆除、退款不计攻方摧毁。堡垒只领取终局奖励，避免升级价值重复加分。

生产溢价只对已完工、资源匹配、已解禁的采集建筑生效，使用该点 inner/outer 倍率和现有取整。只计摧毁时的生产能力，不声称已测到未来停产量。

## 两种配方

`legacy` 默认保持旧权重：伤害、固定击杀、基础建筑石木价、非战斗单位击杀、按阵亡满血量扣分。新增列权重全部为零，以便作为有明确身份的旧对照。

`attrition-v1` 每步计算：

```
Σ 0.1 × 兵种基础价值 × (敌军击杀等级和 − 己方阵亡等级和)
+ 被摧毁非堡垒建筑的基础与已完成升级石木报价
+ 对手实际维修预付木材
+ 2 × 被摧毁采集建筑的当时有效单周期产出
+ 本步攻破堡垒奖励 2000
+ 原 PBRS 距离势差
```

单位基础价值候选：Archer 60、Spear 70、Ranger 90、Scout 30、Mason 60、Ghoul 50、Shade 70、Knight 100、Phoenix 200、Wraith 40、Ram 140。前三项以一级招募价为锚，其余是待标定的支援/攻方交换价值。相同类型和等级正负采用同一公式，生命值不参与。线性等级是假设，不是已经证明的威胁曲线。单位项乘 0.1，用于保留牺牲换破口的空间；不应把不同资源与两方预算看成天然同币种。

一级击杀弓手 +6、工匠 +6；损失不死鸟 −20，损失攻城锤 −14。损失不死鸟并拆掉 120 资源防空建筑为 +100（未含其他战果）。没有单独叠加固定击杀奖、侦察奖、工匠奖或不死鸟死亡奖；原 enemy_unit_gold 仍作实际报价统计。

直接伤害系数为零是本候选的明确选择，不表示伤害没有战术意义。维修消耗单独计价，不再同时按同一伤害付分；该字段包括初始受损及非攻方导致的维修，不能严格视为攻方因果贡献，公平实验要求同初始城市并保留分项。

石/木/金换算默认各为 1；资源停产溢价默认 2 个周期，当前周期为 5 秒，即估计 10 秒停产。重复摧毁会再次领取溢价，它不是潜势塑形，可能高估迅速重建的经济损失；必须把 income_periods=0 纳入等预算调参。工匠情境价值（最后一名 vs 冗余）、不死鸟缺席波数尚未建模，不能用固定加分冒充已解决。

## 使用与恢复

```sh
python train/ppo.py --run-dir runs/old --reward-profile legacy
python train/ppo.py --run-dir runs/new --reward-profile attrition-v1 --credit-assignment team --value-features independent
python train/ppo.py --run-dir runs/new-tuned --reward-profile attrition-v1 --reward-config train/configs/attrition-v1.json
```

这些是选项示例，不是完整的冻结实验命令。JSON 可覆盖 unit_scale、stone、wood、gold、repair_scale、income_periods 和完整 unit_values。未知字段、缺失兵种、负值、非有限数、原生 tally 不匹配均拒绝。单位价值和单位倍率要求非零。

每个 run 保存 reward-recipe.json，包含全部生效系数、胜利奖、折扣和潜势权重。检查点记录同一配方内容及源码哈希；改配置内容或配方后不能 resume，只能新 run。旧 learner/native 的任务必须用其原目录恢复；init-weights 当前载入整份策略权重（含原 value head）；individual+independent 会从该网络复制 critic，team 则新建 critic。因此正式对照必须显式统一 critic 初始化与预拟合待遇，不能假称该选项天然只载入 actor。优化器、奖励曲线和胜率不继承。

## 数值约束与比较

2000 的胜利奖远大于一级单次单位交换，但不是无限刷分情况下的数学支配保证；gamma=.99、时限 2400 tick 暂不一起改。延迟刷 10 个一级猎骑再攻堡的有限例子，必须低于立即攻堡；仍需用真实轨迹检查高等级、长延迟及再生资源循环。

第一轮用同一最新仿真记账运行双方，保留旧机制 individual 与新机制 team 的完整对照，并增加 legacy+team 和 attrition-v1+individual 两个消融，分离奖励与信用效应。critic 结构先保持 pooled/同类网络控制，不能把 entity 改动也揉进唯一一组对照。两边同 actor、同地图/等级/入口、同环境步数、多种子；单独记录初始化 critic 的处理，给予同样的预拟合或归一化预算。后续调参使用相同预算、分离选择与最终评估集。

验收用实际战果，不比较新旧训练分数：堡垒摧毁与耗时、建筑报价损失、各类守军击杀、自损、维修消耗；入口等权，argmax/sample 分报，120/240 秒分报且超时未决。最终还需连续波次验证，不能把单波完成称为跨波训练成功。

## 本次验证

服务器 Release + bindings + ONNX 构建通过。完整 CTest 首轮 67/70，通过修正建筑测试的攻击指令及纯 Python 测试依赖，重建后重跑失败项与相关项 5/5 通过；原生全套为 461 个用例。覆盖误伤、战斗阵亡与运行时移除、升级重建价、资源解禁、旧奖励算术、重复计分、非法参数、训练恢复及配方内容变更拒绝。

使用 gen_01009000、等级 4、混编、守方准备 900 tick、种子 912001 的 8 局 flow_breach 脚本检查，真实击杀、自损、维修、拆除及生产溢价均有非零分项。8 局仅为 4 个入口各重复两次，不是 8 个独立场景，也不是 RL 胜率证据。原始结果保存在服务器 runs/reward-smoke-20260914/scripted-components.json。
