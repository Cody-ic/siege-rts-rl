# 新玩法提案：局域网对战与“我是亡灵”

日期：2026-09-21。状态：**提案待评审，包含已确认方向；尚未实现。**

本提案同时覆盖两个玩法。局域网对战让双方经营、扩张和交战；“我是亡灵”让玩家从攻方视角挑战圣城。现有单人生存模式继续作为独立玩法，新增模式不能代替其开局及中后期配平工作。

## 1. 已确认事项与待评审边界

| 项目 | 已确认方向 |
|---|---|
| 局域网解锁 | 单人生存达到第30波后解锁创建房间；受邀加入不要求自己的单机进度 |
| 对战形式 | 双方使用同一套发展体系，各自经营、建造、升级、招兵；不固定一方守城、另一方按波次攻城 |
| 地图 | 比现有生存地图扩大，双方堡垒位于两个对角区域 |
| 第二玩法 | 第70波解锁“我是亡灵”，由玩家指挥亡灵攻城 |
| 解锁保存 | 模式解锁跨局永久保留；日记、结局和彩蛋仍按当前对局进度，不继承上一局正文阅读权限 |
| 本次交付 | 先提交两个玩法的文档提案，不在本PR中改游戏规则或接入联机 |

下文的配色、网络方案、预算、胜负细节、关卡及实施顺序均是**建议方案**。具体地图尺寸、起始资源、人口、兵力预算、回合数和时限没有定案，也没有经过新模式实测。

## 2. 模式入口、解锁与剧情

建议主菜单增加“局域网对战”和“我是亡灵”；两个模式各有独立的配置、进度和存档标识。

- **局域网**：创建房间在达到30波后开放；加入房间始终可用。参加他人的房间不自动授予创建权限，也不解锁单机剧情。
- **我是亡灵**：建议完成第70波结局呈现后开放，两个结局都能获得，避免用功能奖励诱导剧情选择。提示在结局结束后出现，不能打断文字和过场。
- **模式记录**：用独立的本地模式解锁记录持久化，不把旧的跨局日记合并机制恢复回来。正常对局读档、重开和退出均不能撤销已取得的模式资格。
- **剧情记录**：新单机对局仍重新解锁日记和所选结局；模式资格不意味着可以读取另一结局。局域网及攻城关卡不冒充生存波数。
- **资格来源**：建议仅由普通生存对局触发；开发者跳波、内部测试和联机房间不写正式解锁记录。旧版本进度如何迁移需单独设计，不能为了获取资格破坏或强行转换旧档。

第30波《真相》与第70波《选择》可以作为提示时机的依据；本提案不修改已经审定的故事正文。“我是亡灵”是独立攻城篇，不宣称玩家未选择的结局曾经发生。

## 3. 局域网对战

### 3.1 一局怎么玩

首版建议限制为两名玩家、各一座堡垒，同建筑、兵种与升级规则。双方从等价的初始条件发展，侦察对手、保护资源、控制通道并组织进攻。玩家可以在同一局中主动攻击和回防，不分配永久的“攻方/守方”职业。

建议使用连续时间，不套用单机的自动生波、随波次增长的免费敌军或150秒进攻撤离规则。初版胜负可采用摧毁对方唯一堡垒或对方认输；双方堡垒同一仿真tick摧毁应统一判为平局，避免槽位顺序决定胜负。断线不冒充游戏内认输，处理规则见第6节。

同体系意味着两侧拥有相同的可选项与代价；具体兵种清单仍需验证。先检查现有圣城兵种的攻城能力、兵种克制及驻墙规则，不能仅让两套擅长防守的阵容互相堆塔。若需要攻城器械，优先评估复用现有机制并向双方对等开放，再决定是否需要新增单位。

### 3.2 地图扩大与争夺空间

建议首图采用180°旋转对称，堡垒在两个对角附近但不贴边，留下城内建设、外围驻军和侧袭空间。地图需要至少有正面接触与侧面行动的选择，避免一条窄道把所有策略压成正面堆兵。

- 起始可用资源、行军距离和防守地形等价；可扩张资源在双方外围与中部形成争夺。
- 中部资源值得冒险，但不把先到一次变成无法逆转的永久优势。
- 以首次接敌时间、增援时间和有效争夺面积选择尺寸；单纯拉大空地会放大等待。
- 生存地图的单堡垒、敌军集结区、环带与资源 `unlock_wave` 规则不能直接复用。新地图需定义双方出生区，资源解禁改为独立的对战规则。
- 首版先验证固定地图，再考虑随机生成；交换出生位置重复测试，不能仅凭几何对称宣称公平。

当前格子槽位使用16位编码，`World` 要求总格数小于65535，**256×256已被拒绝**。可先在现有容量内选更大的候选图；若玩法需要更大尺寸，须联动修改命令、登墙目标、序列化及相关工具，不能只改地图JSON。

### 3.3 两方建筑和士兵怎么区分

建议使用蓝色与橙红色作为两队初始配色，同一玩家在双方客户端保持相同队色，并辅以不同纹章形状。

| 对象 | 建议呈现 |
|---|---|
| 士兵 | 盾面、披风、衣服饰边采用队色，盔甲、皮肤与武器保留原色 |
| 建筑 | 旗帜、门口纹章、屋顶局部使用队色，保留石材和木材质感 |
| 墙门 | 城门及间隔墙段设置队色旗帜，连续墙面仍可辨认归属 |
| 密集交战 | 细队色脚下标记辅助识别，选中时加粗；不用颜色承担全部识别工作 |
| 小地图和面板 | 与世界队色一致，显示玩家名字；只绘制本方可见或规则允许记忆的信息 |

框选默认只选择自己的单位和建筑；点击敌方显示侦察允许的信息，不出现己方建造、升级操作。目标死亡、句柄复用或退出视野后，标记和菜单必须正确更新。

先用旗帜、地面标记和面板验证远近景识别，再完善精灵的局部队色区域。视觉验收至少包含近景混战、远景军团、建筑重叠和色觉差异下的形状识别。

## 4. “我是亡灵”

### 4.1 核心循环

建议首版为固定城防的单人关卡：选择目标圣城 → 侦察与配兵 → 指挥进攻 → 必要时撤回整军 → 再次突破 → 攻下堡垒结算。关卡可以分别强调坚固墙防、密集箭塔、外围经济与混合防御。

不要求先完成守方RL训练。优先用可解释的守方脚本与真实资源验证玩法，但不能把当前自动守方直接视为已合格的对手。

### 4.2 玩家控制与兵种职责

玩家需要框选、编队、移动、指定攻击、攻击前进、停止和撤回。沿用现有攻击能力与可见性限制，明确区分“攻击这个已知目标”和“向这个位置推进”。

| 现有兵种 | 人控玩法要验证的用途 |
|---|---|
| 亡灵步兵 | 前线推进、牵制和保护攻城部队 |
| 亡灵法师 | 压制墙上及城内守军 |
| 鬼域骑士团 | 利用机动性袭扰经济、截击与转线 |
| 攻城锤 | 选择破口，集中拆除墙门和关键建筑 |
| 不死鸟 | 判断薄弱防空，清除后袭击其覆盖区；保留既有结构攻击限制 |
| 幽影窥使 | 执行侦察与情报传输，让配兵和突破方向有依据 |

表中是预期用途，不是现有克制关系已经配平的结论。自动行为负责寻路、射程内接敌等执行细节；明确的玩家命令优先，原攻方脚本或RL不得在下一拍把命令覆盖。无效目标要有反馈，不能假装接受命令后一直停住。

### 4.3 预算、连续进攻与胜负

建议为每关提供有限的总兵力预算，用于编队、等级和损失补充；预算及补充规则开局明确显示。拆塔、破坏经济、击杀工匠是攻下堡垒的手段，不直接替代胜利目标。

- 建筑损毁、守军伤亡和经济损失延续到后续进攻，守方只能按正常资源、工匠与训练规则恢复。
- 攻方存活单位及其伤亡保留，不能每波无成本重新满编。撤回、重组和补员的具体代价待实验。
- 不死鸟保留身份、重生等待与占用名额的代价；关卡结束判定必须考虑等待重生的单位，避免活跃部队刚被清空就误判失败。
- 建议堡垒摧毁为胜利；没有可用部队、可补充预算或合法待返部队时失败，玩家也可主动认输。
- 限制进攻次数或总时限属于待评审选项，不直接移植生存模式150秒撤离。测试真实僵持、绕路和修复消耗后再定，界面提前告知条件。

自由撤回不能变成无代价刷满血，守方也不能在场景间免费恢复城市。伤兵恢复、撤离耗时和多波持续性是需要实验的规则，提案不默认新增治疗建筑或复活资源。

### 4.4 守方与剧情边界

第一座城的守方至少要能守住岗位、保护工匠、修补缺口、补充兵员，并依据真正看见的空军调整防空。固定的是关卡起点和防御计划，不是让单位原地挨打；它不得透视攻方编成、凭空补兵或免费修复。

先保证固定关卡能提供可信对抗，再考虑自主扩张和更多策略。#205的实验说明中，已有默认守方在固定场景第4波失守的记录，不能用回归测试通过代替对手质量验收。对应说明是开放PR中的实验，尚未随正式版发布。

“攻打自己曾经建造的城”列为后续扩展：需要只读复制城市、校验版本，并重新评估守城资源与攻方预算。不能直接把玩家存档拿来改写，也不能把一座90波城市当成已经配平的关卡。

## 5. 共用基础与现有代码差距

基线为本提案分支起点 `7b93f1402dbe2f27d0ddfdebc238efd4be1bc62b`（main）。后续玩法分支是参考，不作为已经合并的事实。

| 范围 | 当前约束与需要解决的问题 |
|---|---|
| 玩家归属 | `rts_core/include/rts/roster.hpp` 的 `side_of(type)` 按兵种划分敌我，建筑默认属守方；同兵种对抗必须把所属玩家与兵种分开，不能复制一套枚举冒充第二玩家 |
| 世界状态 | `rts_core/include/rts/world.hpp` 中堡垒位置、资源库存等按单个守方城市组织；需要每玩家的堡垒、经济、人口、训练和败局判定，并审计全部相关调用 |
| 视野与交互 | 现有视野层可参考，但读取、渲染、拾取、命令权限与敌我伤害都要按实际所属玩家，不能只换颜色 |
| 地图 | `game/include/game/map_data.hpp`、加载器及 `tools/map_gen/` 需要独立的双出生区模式与校验，保留原单机地图的合法性 |
| 人控攻方 | `DemoBattle` 目前生成攻方行为；需要独立的人控命令入口、命令持续状态及控制权仲裁，避免AI覆盖 |
| 网络 | 检查的核心、游戏、渲染与构建源码中未发现现成联机层；现有固定20Hz、命令与快照可复用，但不能据此声称联机已经接近完成 |
| 兼容 | 玩家归属、命令和状态布局变更需同步处理规则指纹、地图/存档版本、回放、Python绑定与训练观测；不能给旧模型改标签假装兼容 |

建议在模式边界区分“生存”“局域网对战”“亡灵攻城”，共享单位战斗与指挥能力，经济、出生规则和胜负由各模式明确提供。旧生存模式通过适配保留原有攻守关系，不把双人对战的资源与人口数值直接套回去。

人口、攻方编队数及守方建筑数量需按新玩法单独测量。训练中的agent规模限制不自动成为人类对战上限；扩大地图与双方军队后，也不能凭两三个寻路微基准就宣称整局性能足够。

## 6. 局域网实现建议

建议首版由房主维护权威仿真，客户端发送操作请求，房主在固定20Hz仿真中校验、排序并执行，再发送各玩家允许看到的状态。客户端负责显示和输入反馈，不自行决定资源、伤害或胜负。

- 房间握手核对程序规则版本、数值及地图内容；不兼容时明确拒绝开局。
- 操作携带玩家身份、递增序号和目标完整句柄；校验所属权、费用、可见性与命令合法性。重发不得重复扣费或重复招兵。
- 保存房主实际采纳的tick与操作顺序，用于复现争议；双方同tick操作遵守公开、稳定的规则。
- 发给客户端的状态按其视野裁剪，不能发送完整隐藏城市后仅在画面上涂黑；房主完整快照仅供权威保存。首版信任房主，不宣称具备竞技级反作弊。
- 客户端可插值显示，但仿真仍按固定tick运行。协议和发送频率用两机测试确定，不在提案中锁定某个网络库。
- 首版建议手动地址加入，局域网房间发现作为便捷入口；不承诺互联网匹配、账号服务或公网穿透。
- 必须处理失联：建议暂停并提供明确的重连宽限，超出后双方看到一致的中止结果。宽限时长、重连续局和正常暂停权限仍待定；首版不做房主迁移。

现有确定性帮助房主回放与故障定位，并不自动保证不同编译器的双机全状态锁步。本方案不要求一开始就让两台机器独立算出完全相同的整个世界。

## 7. 建议实施顺序与验收

各阶段应独立提交代码PR；阶段结束前记录实际测试结果，不以本提案合并视为功能验收。

| 阶段 | 可审阅交付 | 通过条件 |
|---|---|---|
| A：约定与人控原型 | 模式/玩家归属契约；现有攻方阵容的人控指挥原型 | 指定目标、移动、停止、撤回实际生效，脚本/RL不抢控制；无效命令有反馈 |
| B：单城攻城 | 一座固定圣城、守方脚本、有限预算和完整结算 | 能从开局打到胜/败，损毁与补员规则真实生效，无无限免费补兵或假死僵持 |
| C：双玩家离线仿真 | 双堡垒、双经济、同兵种敌我、队色及独立视野 | 两套输入可在同一进程完整交战，越权操作被拒，双方胜负对称，旧生存模式回归通过 |
| D：双机局域网 | 建房、加入、版本协商、输入与可见状态同步、失联处理 | 两台机器完整对局，延迟/抖动/重发及断线情境可复现，无重复执行和隐藏情报泄露 |
| E：地图与关卡 | 扩大对战地图、多种城防关卡及配平报告 | 换边、多策略、多种军队规模测试；量化接敌等待、战果、修复消耗及整局性能 |
| F：正式入口 | 30/70波解锁、跨局模式记录、说明与发布包 | 建房资格、自由加入、模式永久解锁和本局剧情互不串扰；结局提示不打断呈现 |

“我是亡灵”的可玩性不等待新的RL长训练完成；局域网正式接线以前必须先验证同体系双玩家的规则。阶段A的交互原型不意味着可以绕过阶段C的归属改造。

### 验证清单

- 规则：同类型敌我识别、独立库存与人口、不能维修/升级对手建筑、塔弹与单位溅射按所属权正确结算、同时摧毁堡垒结果一致。
- 情报：侦察有收益；退出视野保留的记忆与未知新建/修复区分；小地图、面板、网络消息不泄露隐藏实体。
- 对战：双方交换出生点，分别尝试快攻、扩张、固守、侧袭和混合兵种；记录胜负、交战时间、资源支出、军队损失及是否出现永远拆不动的城。
- 攻城：纯堆兵与侦察配兵对照；拆矿、拆防空、破墙等选择有实际收益，也有可解释的失败；真实僵持单独分析，不统一归为超时。
- 性能：Release测量双方高人口、密集建筑、寻路和视野刷新同时发生时的tick耗时、帧率、输入响应与网络流量。20Hz对应每tick50毫秒预算，须保留余量并测尾部耗时。
- 兼容：模式记录与单机剧情记录分离；旧档被明确识别与保留；新模式的存档、回放与重连恢复一致。改动核心接口时运行相应C++、绑定和训练测试。
- 视觉：队色与纹章在混战、缩放、重叠和不同地图背景下可读；敌方菜单不出现己方操作。

## 8. 本轮不定案的事项

1. “达到30波”是否在进入建造阶段立即计入；70波是否以结局呈现结束作为入口开放时点。
2. 对战地图具体尺寸、起始资源/守军、人口与升级节奏，以及是否需要对称开放攻城器械。
3. “我是亡灵”的总预算、补充节奏、撤回与伤兵规则、进攻次数/时限及关卡难度。
4. 联机暂停、失联宽限、恢复对局与地图传输范围；首版是否提供房间自动发现。
5. 旧版里程碑导入模式记录的规则，不能靠重新读取旧跨局日记解锁所有剧情。

以上需要原型与玩法评审，不要求现在一次性拍完。当前原生存模式的中后期战术、士兵作用和守方AI质量仍需继续改进；增加两个入口不会自动解决这些问题。
