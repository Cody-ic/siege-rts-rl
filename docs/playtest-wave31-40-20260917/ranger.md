## 2. 为什么会不攻击

`game/src/defender_script.cpp` 第425—444行的猎骑分支依次执行：

1. 骑士距离不足3格，直接返回驻防点。
2. 统计4格内敌我战斗单位，查找城内且距堡垒不超过8格的地面目标，给幽影单位额外优先。
3. 自己在城圈外、敌人数大于友人数加1，或生命低于40%，直接返回驻防点。
4. 以上均未触发，才检查能否攻击，再决定追目标或待命。

**低血回撤在攻击判断之前，而且不是“撤回后恢复正常”的临时状态。** 当前守军生命写入只有生成、承伤、移除和快照恢复，没有治疗或自动回血。只要生命一直低于40%，下一次自主决策仍会走回撤分支，即使敌人已经贴身也不会在这条分支选择攻击。

临时手动指令优先于自主规则，可以覆盖这一行为；到达目标后指令结束，又回到同一套判断。因此不能将其表述为任何操作都无法令它攻击。跨决策间隔仍可能完成先前承诺的攻击，也不等于撤退分支会新发起攻击。

## 3. 回到家还来回走，是另一个明确问题

正常待命的 `hold_position()` 会判断距离驻防点1.5格内就停止。猎骑的危险/低血分支直接调用 `move_towards()`，绕过这个到达判断；寻路到目标格后，又有朝格子中心继续移动的兜底。

旧猎骑2490384在第36波的采样中，反复在约 `(83.02,87.04)` 至 `(83.92,87.94)` 间来回移动，生命始终172。两名旧猎骑整个主区间的采样动作都是移动，没有攻击。这种移动不代表巡逻或正在找机会，而与“没有到位停止的回撤”规则相符。

## 4. 为什么保守限制仍不能保证有效作战

- **人数判断过粗。** 4格内每个战斗单位算一人，友军包含自己；不考虑等级、血量、实际输出、能否攻击目标，也不计塔的支援或误伤。它不能替代局部交战风险评估。
- **回撤方向固定。** 躲骑士时朝堡垒附近的驻防点移动，并非选择远离骑士且可通行的安全路线。特定站位下，这两者可能相反；本段尚未做相应反事实验证。
- **自主活动范围与外围防线脱节。** 主动追击目标需在“城内且距堡垒8格以内”。玩家塔阵和经济向外扩张后，猎骑没有自动保护那些外围设施的职责。
- **“城内”判断并非真实围合区域。** 使用现存所有墙与门坐标的外接矩形，不核对连通封闭性；零散外墙也能改变这个范围。堡垒8格限制仍然单独生效。
- **友军火力会快速触发长期退出。** 本段两名新猎骑共只命中四次，却承受882点己方箭楼伤害。单纯加攻击或降低撤退线，不能消除近战进入箭雨后失去使用价值的过程。

## 5. 建议的处理顺序

1. **修正回撤控制。** 到安全点后停止；回撤时评估路线，无法脱离或被贴身追击时保留自卫能力，避免把“保护单位”实现成无条件拒绝战斗。
2. **补齐受伤后的用途。** 明确休整、付费治疗或伤兵替换的规则。若允许恢复，需要评估耗时、金币成本、所在位置及可被打断性；不能直接假设免费波间满血对配平无影响。
3. **重新明确机动兵职责。** 以玩家指定防区或需要保护的外围设施为依托，限制追击距离；风险判断至少区分敌方兵种、当前血量和友军支援，不能只数人头。
4. **一起评估友军箭雨。** 检查落点选择、近战避让和误伤强度。是否削弱误伤属于配平选择，不能从单局直接推导为全部取消。

验证应同时检查存活、有效输出、保护工匠/建筑的效果、重返战斗所需时间，以及闲置人口，而不只看少死了多少猎骑。

现有数据与源码足以确认低血循环和到位不停的问题；哪种恢复机制、支援范围或误伤数值最好，仍需对照。原始记录见本地证据包（材料范围见[证据说明](evidence.md)）中的 `data/units.csv`、`data/damage.csv`、`reference_source/game/src/defender_script.cpp`；参数和手动状态可查 `data/snapshot_95979.json`。
