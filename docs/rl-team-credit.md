# 团队信用调整：第一阶段

## 已改动

在 #181 的 `5cd4dfd` 上增加可选 `credit_assignment=team`，保留默认 individual。
策略仍共享原 actor；新增独立团队价值网络，用已有迷雾观测的池化特征估值，
不使用全图隐藏状态。初始化该网络不消耗 actor 的 CPU 随机流。

每个环境步存一个团队值与回报；编队死亡不截断团队 GAE，行动样本仍按真实存活行
选择。团队 critic 每轮按环境步训练，避免按人数重复计价；零 actor 尾段也训练
critic，但不更新 actor。actor 旧 critic 头冻结，模型导出结构不变。

团队模式使用已有团队 PBRS，不再套个体死亡边界修正。世界终局仍将势归零，
不能同时保留旧修正，否则会给死亡编队额外奖励/扣分。原 individual 分支完整保留。

团队模型/优化器独立写入 checkpoint；配置和学习器哈希版本更新，拒绝静默跨契约续跑。
初始化只能显式载入 actor 权重，团队价值重新训练。团队 value_loss 独立记账。

## 范围与未完成项

这仍是固定单波环境。超时、全灭、Keep 摧毁是原任务终局，rollout 结束仅 bootstrap。
辅助 GAE 提供截断参数，测试验证不会将新城市奖励漏进旧城市，但目前单波适配并不
把超时改成截断。换波接续的测试是算术边界验证，不是原生跨波训练验证。

未接入 TrainingCampaign 的攻方逐编队动作，未训练持续城市，未改奖励定价、gamma、
目标选择、网络观测契约或游戏配平；未启动服务器长训练。训练恢复沿用原机制：
未完单波重启并计数，只有在完整 episode 边界才保证本次测试中的逐参数恢复一致。

池化抹去了局部空间结构，作为团队价值基线可能欠拟合；多个编队视野重叠也不等于
城市真实统计。它不能完整表达维修、经济中断及长期城市状态。与旧模式对比同时
改变了价值结构和信用边界，先确认链路，再做控制 critic 结构的纯信用消融。

## 验证要求

`team_credit` 测试覆盖延迟团队胜利、无 actor 的弹丸尾段样本筛选、截断 bootstrap
与新城隔离、真终局、rollout 续值、PBRS 望远镜抵消、观测池化与 padding、随机流、
原生短训练的团队权重更新、完整单波边界恢复逐参数一致及损坏 checkpoint 回退。
原有 PPO/评估测试继续验 individual；新模式不以回归通过声称战斗能力提升。

后续需要先完成最新原生 ONNX 导出/动作一致性，再做冻结三图实战对照；跨波采样
必须保留真实城市与控制器状态，不可只改 done 标志后继续使用新生成的世界。

Windows/MSVC Release，开启 Python 绑定及训练测试，关闭渲染与 ONNX。
重新配置、完整构建后 CTest 69/69 通过（300.49 秒）；新增 team_credit 包含 7 个
用例，含真实原生环境与 PyTorch 短训练。队友 #181 的连续评估回归也通过。
`git diff --check` 通过。以上证明链路与回归，不证明三图胜率提升或 GPU 训练表现。
