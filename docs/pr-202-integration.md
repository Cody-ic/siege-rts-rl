## 教师频率排查

实际模仿采集入口 `macro_imitation.py` 默认每 **20 tick（1 秒）** 下令；宏观 PPO 默认 100 tick（5 秒）；队友指出的测试使用 **500 tick（25 秒）**。教师每次只取一条合法命令，完整脚本每 20 tick 可提交多条命令并下达调兵指令，两者能力边界不同。

用当前整合版本、正式数值、seed=101，在三张地图观察完整第一波，窗口最多 10000 tick。表中括号是波末堡垒剩余血量占当时最大血量的比例，失败均为真实堡垒陷落，没有超时。

| 地图 | 完整脚本 | 教师 1 秒/次 | 教师 5 秒/次 | 教师 25 秒/次 |
|---|---|---|---|---|
| gen_01009000 | 守住（59.2%） | 守住（45.7%） | 守住（55.7%） | 战败 |
| gen_01001000 | 守住（69.6%） | 守住（24.3%） | 守住（17.5%） | 战败 |
| gen_01004000 | 守住（40.0%） | 战败 | 战败 | 战败 |

因此，25 秒的测试频率确实会限制教师表现，但不能将教师的全部弱点归因于频率。实际采集频率也有首波败局，且某些场景低频反而剩余血量更多。本次没有修改教师决策、游戏强度、生产训练频率或真实模型权重；需要独立评估教师行为与示范质量后再决定训练方案。

这是三图单种子的诊断，不是泛化胜率或后期配平结论。原生仿真指纹、命令统计和状态哈希见 [JSON](pr-202-integration/teacher-cadence.json)，简表见 [CSV](pr-202-integration/teacher-cadence.csv)。构建当前绑定并设好 `PYTHONPATH` 后，可在仓库根目录复现：

```python
import sys
sys.path.insert(0, "train")
from macro_evaluate import evaluate_case
for name in ("01009000", "01001000", "01004000"):
    for controller, period in ((None, 20), ("teacher", 20), ("teacher", 100), ("teacher", 500)):
        print(evaluate_case(f"game/data/maps/pool/gen_{name}.json",
            "game/data/stats_placeholder.json", 101, controller, period, 1, 10000))
```

冻结评估可对当前版本兼容的检查点使用 `--arms script teacher learned --period 20`。报告明确记录周期；旧规则检查点仍执行兼容性检查，不通过改元数据强行加载。
