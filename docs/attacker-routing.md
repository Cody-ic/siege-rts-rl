# 攻方共享情报与承伤寻路

旧脚本虽然比较绕路与破墙时间，却不计算沿路火力；99 级攻城锤仍用 8 级代表值估价，并把实际重叠的前摇与冷却相加。它也直接读取所有实时建筑，缺少侦查成功与失败的信息差。

## 情报规则

- 普通战斗单位共享视野与建筑记忆，队员的发现也能交给其他编队。地面单位受森林、岩壁遮挡；空中单位按原规则不受遮挡。
- 窥使亲自观察城防并完成 60 tick 传输，交付**该时刻一次性的全局建筑快照**；在此之前死亡或失去观察不交付。全局情报立即可用于本波路线，原有下一波编成报告时序保留。
- 记录建筑位置、类型、当时血量、等级、完工状态与观察 tick。离开视野后不遗忘；隐藏维修、拆除、升级或原址重建不更新。再次看到时更新，看到空地才删除。
- 记忆跨波保留，后续成功侦查刷新全局。普通观察始终可以局部更新。窥使自己的视野不充当普通编队观察，也不会借道沿途资源目标或不死鸟追击判断泄露建筑。
- 地形仍为公开信息；本批全局快照不包含守军实时位置。共享记忆按地块排序，不依赖可以被复用的建筑槽位。

## 路线计算

脚本调用 `FlowField::compute_known`，只提供上述建筑记录。按兵种、**实际等级**及目标集共享路径场，各成员从当前位置采样。每个决策拍更新观察并重算，所以看见缺口被补上后会重新比较。

一条边的代价为：

```text
行军 tick + 破坏 tick + 200 × 预计承伤 / 该等级单位满血
破坏 tick ≈ 1 + 首次前摇 + (所需命中次数 - 1) × max(冷却, 前摇 + 1)
```

弹丸兵种另加相邻格的首发飞行估计；不预测骑士冲锋额外伤害。200 tick（10 秒）是可调候选权重，意味着允许用约 10 秒额外行军换取一整条血量的保护，尚未由长局配平确定。

火力按已知建筑的等级、伤害、冷却、射程及对空/对地能力累计；工地不产生火力，已完工建筑维修时仍产生火力。行军取相邻格平均火力，破墙停留按墙外出发格的火力计算。攻城锤遵循选定路线，靠近路线上的阻挡物由仿真自动破坏，不被“最近墙”动作抢走路线。

## 进攻时限

每波进攻上限从 120 秒（2400 tick）调为 150 秒（3000 tick），增加 25%，给绕路避火和破墙留出余量。这是试调值，尚未通过长局对照确定最佳时长。只累计进攻阶段；攻方提前失去战斗能力仍立即清波，达到上限则按原规则撤走残兵。首波 45 秒、后续 33 秒的建造期保持原值。

此默认时限用于游戏对局（包括加载 RL 策略的对局）；训练 episode 截断、分析工具的总运行窗口仍由各自配置控制。

## 验证与边界

`tests/attacker_routing_test.cpp` 使用种子 17：

- 共享观察、地形遮挡、窥使成功/被拦截、一次性快照、隐藏原址重建、观察空地后移除，以及实时世界变化不能改变未更新的路线。
- 1/8/30/99 级攻城锤，前摇 0/30/70 tick、冷却 60 tick，与真实引擎逐 tick 击破 1200 血城墙的时间一致（直接攻击、没有守军和维修）。
- 同一墙线，无火力时选择缺口；火力覆盖缺口时改为破墙；火力转移到墙下又改走缺口。
- 32×16 隔离场景：步兵从 (7,8) 前往 (17,8)，墙线 x=12、缺口 y=3、80 血突破段 y=8，塔在 (12,2)。旧路线 55 tick、损失 80 HP；新路线 96 tick、损失 0 HP。使用瞬时弹丸和无守军场景隔离路线影响，这不是正式数值配平结果。
- 共享记忆随完整快照保存；正常操作日志重新推演得到同一记忆及世界哈希。

Windows/MSVC Release、前端开启、警告视为错误：重建后 `[routing]` 的 11 个用例、1146 条断言通过。相关 CTest 11/11 通过，包含战斗、寻路、对局、宏观/单兵脚本、迷雾、回放、批量环境、存档和确定性禁令；补充测试后重建并再次通过相关 3/3，最后新增的隐藏状态恢复与实际等级用例包含在上述 `[routing]` 结果中。

150 秒时限调整后再次重建 Release，`ctest --test-dir build-verified -C Release -R '^rts_tests_(macro|demo|save)$' --output-on-failure -j 3` 的 3/3 项通过（121.67 秒），覆盖默认值、超时撤离、波次循环、不死鸟留存/重生和存档恢复；旧版拒绝并备份的用例扩展至 v17。此轮未重新开展长局配平实验。

时限调整前的开局检查：12 张演示地图、种子 1、宏观守方开启，各运行 2400 tick（每局总观察 120 秒），全部正常完成，合计 28800 tick，运行耗时约 55.27 秒。全部在第一波被观察窗口截断，因此只证明开局运行，没有声称通过 3 波或取得长期平衡结论，也未覆盖延长后的超时边界。汇总见 [map-smoke.csv](attacker-routing/map-smoke.csv)，原始 JSON 在忽略的 `build-verified/routing-map-smoke.json`。当时使用的命令：

```sh
calibration_runner --maps game/data/maps/pool --seeds 1 --max-waves 3 --max-ticks 2400 --macro --out routing-map-smoke.json --compact
```

本批只估计建筑火力，没有预测移动守军、维修速度、友军分担或躲避弹丸。也未实现“先拆某座塔，再重新估计整段路线”的多阶段搜索。不会把测试结果表述成敌方战术已全面修好。

已训练 RL 支持的单位仍由模型输出最终动作，旧 `FlowField::compute` 及其三档观测输入保留；本批直接改善脚本模式及 RL 未接管的单位，不是新训练成果。训练侧迁移情报与路径观测需要独立升级契约、重新训练并评估，不能静默替换旧模型输入。

时限调整后基础存档升为 v18，战术/宏观为 v19/v20；旧版存档保留备份、由对应旧程序继续。本分支未更新已安装的正式版。
