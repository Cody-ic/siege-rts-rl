# RL 复盘修正

复盘发现三个需要先于长训练解决的测量问题。本修复依赖 #182，不改变其团队信用结构。

## 误伤与敌军战果分开

范围攻击按游戏规则仍然会伤到友军；原先按伤害来源累计战果，却未排除友军，使误伤
进入正奖励。现在单位伤害、击杀、侦察/工匠击杀及守军补充价格只统计敌军。
`friendly_unit_damage`、`friendly_units_killed` 单独记录实际误伤，奖励系数为零；
自身阵亡损失和不死鸟战斗死亡仍正常记录。双方都适用，超杀不增加实际伤害。

原奖励权重和 gamma 不变；修正计数会改变训练目标的实际取值，因此 learner 升为 9。
旧检查点不能绕过契约恢复，新试验需开新目录。尚未证明旧模型主动利用误伤奖励。

## 连续战役注明模型范围

`CampaignTransition` 记录进攻阶段每 tick 开始时存活战斗单位的模型支持/脚本控制
数量，报告汇总至每波及整场。建造阶段和侦察单位不参与统计；没有战斗时比例为 null。
超出支持兵种或等级即计入脚本范围。这是覆盖统计，不是动作执行次数或协作证明。
模型组明确标作 `frozen_policy_with_script_fallback`，避免把脚本接管后的胜利当成纯 RL 胜利。

## 超时延长复查

冻结评估增加 `--timeout-review-ticks`。原窗口内的胜率、超时数和每局战果保留，超时局
在同一座城市继续到复查上限，后续结果放入 `timeout_review`。报告另列后续胜利、全灭
和仍未决数量。不会重置城市，也不改变训练终局定义；参数必须对齐决策周期。

回归覆盖：攻方近战溅射、守方齐射误杀工匠、双方死亡损失、窗口内原始结果保持、
晚于原上限的 Keep 胜利、同入口/种子接续、战役覆盖分组和启用 ONNX 的模型参与统计。

这些修复使下一轮比较可信，不构成更优策略已训练完成的证据。
