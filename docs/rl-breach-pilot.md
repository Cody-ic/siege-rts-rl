# 破口推进：先修正示范行为，再验证 PPO 接续

本轮沿用固定九支一级亡灵步兵编队、实际距离、真实脚本守方和 2400 tick 时限，原生仿真、观测、13 个动作、网络与 PPO 奖励均未修改。所有训练和评估在本地 Windows CPU 完成，不使用共用服务器 GPU。

## 从动作记录定位问题

上一轮示范 + 32,768 步 PPO 的两图记录中，存在合法攻击机会时，模型没有选择非攻击动作的情况；但第二张图最大概率模式在入口 0 的六局完全没有进入合法攻击范围。入口 4 的模型则没有选择过 `AtkBld`，规则 flow 在该入口六局全部获胜。因此不能仅凭“到城下没有赢”归因于不愿攻击。

原生 `tick_unit_combat` 会完成已经承诺的攻击前摇，移动也会等前摇结束；这次没有找到“每次换动作取消已开始攻击”的问题。真正值得比较的是接近路线和墙边的目标选择。

原 `flow` 示范顺序是 `AtkBld → AtkWall → AtkNear → 行进`。攻击掩码判断射程内是否有目标，**移动掩码主要判断地形，不保证目的格没有建筑**；方向场则把建筑破坏时间计入通路代价。原生移动已有 `try_bump_attack`：实际目的格被可破坏实体占据时，破坏挡路实体，随后继续走。原老师“附近有墙就打”的选择可能阻碍通过已有通路，也使网络学到这个偏好。

新增 `flow_breach` 仅作为可选老师/规则对照：先攻击射程内的非墙建筑，否则沿方向场走，由既有碰撞机制处理挡路建筑；没有合法行进选择时回退原攻击规则。它只读公共观测与合法动作，不按堡垒坐标暗中覆盖模型指令，也没有新加游戏自动战术。旁侧墙和近身敌军可能被放过，所以不能把这个老师视为所有兵种的最优策略。

## 试验口径

训练仍只用 `gen_01001000.json`。收集 5 种距离、每种 4 环境各 300 次决策，共 6000 teacher env-step，得到 12,522 条示范；随机种子 1、12 轮拟合、批大小 256、Adam 学习率 0.0003。示范不拟合价值函数。原老师对照使用上一轮独立保存的 12,252 条示范及其模型。

前两张图采用与上一轮相同的评估种子、编成和时限，每项 32 局，分别轮换四个、五个入口。第二张图 `gen_01002000.json` 本轮已经参与诊断和方案选择，应当称为**诊断验证图**，不再当作最终未见测试集。

同一入口会重复抽样，32 局不等于 32 种城防布局；固定编成下，确定性执行的重复结果尤其不能当作广泛泛化的证据。

规则原型的两图各 32 局结果为 16/32、32/32 胜；原 flow 为 0/32、6/32。规则成绩只用于可行性对照，不能作为 RL 胜率。交付实现另与原型逐局核对终局、决策数和全部结算指标。

仅做新老师的示范初始化，冻结最大概率/概率采样执行分别为：训练图 **16/32、17/32** 胜，诊断图 **6/32、14/32** 胜，四项均 32/32 接触建筑。这说明网络能够学到部分突破行为，但明显没有完整复现老师；不可把老师在诊断图 32/32 的结果套给模型。

本轮还用原老师数据做过一次仅拟合阶段的旋转/镜像增强初筛：没有新收集环境步，额外拟合 12 轮，同图两种执行方式都是 0/32 胜，诊断图为 0/32、1/32。该候选保留为试验记录，没有并入生产训练脚本。它提示方向覆盖值得继续研究，但单靠增强不足以代替对示范战术本身的检查。

胜利会提前结束对局，因此成功突破的策略可能有更少的总建筑伤害。仍同时保留接触率、拆毁价值、伤害和按入口结果，不把消耗战收益删掉或只按伤害挑模型。不同老师的示范条数略有不同；即使 PPO 步数相同，也不声称总算力完全相等。

## 两组有限预算的 PPO 接续

从同一份新初始化权重另开两个目录，各跑 **32,768 env-step / 32 次更新**。配置为 16 个环境、2 个原生线程、2 个 PyTorch 线程、种子 1、实际距离课程 `1.0`、原经济奖励。两组配置逐项核对，唯一差异为学习率 **0.0003 / 0.00003**；初始化权重未被覆盖。共新增 65,536 PPO env-step，没有自动扩大到长训。

| 模型 / 执行方式 | 训练图胜局 | 训练图接触 | 诊断图胜局 | 诊断图接触 |
|---|---:|---:|---:|---:|
| 初始化 / 最大概率 | 16/32 | 32/32 | 6/32 | 32/32 |
| 初始化 / 概率采样 | 17/32 | 32/32 | 14/32 | 32/32 |
| PPO 0.0003 / 最大概率 | 0/32 | 32/32 | 0/32 | 32/32 |
| PPO 0.0003 / 概率采样 | 0/32 | 32/32 | 0/32 | 32/32 |
| PPO 0.00003 / 最大概率 | 8/32 | 24/32 | 0/32 | 19/32 |
| PPO 0.00003 / 概率采样 | 8/32 | 24/32 | 0/32 | 20/32 |

默认学习率下，训练图最大概率模式的平均拆毁价值从 132.50 升至 282.50，但胜局归零。较小学习率保住部分同图胜局，却失去部分入口的接触能力，不能称为修好了 PPO 接续，也没有因此修改训练默认学习率。

**本轮保留初始化模型作为突破对照，不以两份最新 PPO 权重替换它。** 这不代表取消经济消耗战目标：现有结果不足以单独归因于奖励偏向、价值学习对共享特征的影响或短预算波动。下一次改进应针对示范能力保持、不同地图的路线覆盖与经济/胜利目标做受控比较，先通过同口径复测，再增加训练预算。

## 未参与调参的第三张地图

在观察第三张图的结果之前，固定检验**仅示范初始化**的权重。使用 `gen_01003000.json`、种子 300001、五个入口、每项 32 局；该图既不参与收集/拟合，也没有用于修改本轮两个 PPO 配置。下面的模型成绩不代表 PPO 接续后的成绩。

| 策略 | 接触建筑 | 胜局 | 平均建筑伤害 | 平均拆毁价值 |
|---|---:|---:|---:|---:|
| 初始化，最大概率 | 26/32 | 7/32 | 2,108.06 | 82.81 |
| 初始化，概率采样 | 32/32 | 8/32 | 3,007.56 | 81.88 |

最大概率模式在入口 3 的六局没有接触建筑，说明路线泛化仍有缺口。模型距离老师的成绩也很远；三个固定布局、单兵种和单训练种子不足以证明稳定攻城策略。这轮结束后没有据此继续调参并反复使用该图冒充新的独立测试。

## 恢复与兼容

`demonstrations.py collect --teacher flow_breach` 显式选择新老师，原 `flow` 默认值保留。收集计划和导出说明记录老师，换老师必须另开目录。拟合仍按完整轮次保存模型、Adam 和随机状态；PPO 使用导出权重显式热启动，随后恢复它自己的检查点。

此次更新示范/评估源码指纹，旧示范与实验编排目录应使用旧版本代码恢复，或新建目录；上一轮产物对应提交 `115a35d`。PPO 学习器、原生绑定合约未改，已有 PPO 完整检查点的恢复路径不受影响。模型冻结评估经测试确认不调用两个老师。

验证：24 项真实原生环境 + CPU PyTorch 运行时检查通过，新增覆盖合法回退、不修改输入、新老师的收集/拟合恢复及换老师拒绝；之后补充“模型推理不调用老师”断言并单独重跑通过。交付规则与原型/旧规则共 32 局核对，终局、决策数与所有结算指标逐项一致。三份新导出模型各 12 个张量且全部有限，初始化权重哈希未变；两个新 PPO 合约与上一轮 PPO 相同。纯 Python 工具改动未重跑无关的整套 C++ 测试。

本轮训练产物保存在本地 `runs/breach-pilot-20260908/`，不提交 Git。机器可读结果与文件校验记录见 [试验证据](rl-results/2026-09-08-breach.json)。单训练种子、少量固定地图与固定兵种仍不足以证明完整游戏 AI 或稳定泛化。
