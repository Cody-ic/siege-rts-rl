# 工匠城门徘徊修复

## 复现与原因

2026-09-21 试玩存档在第1波、tick 1037，工匠收到城外工地的普通移动命令，却在城门旁左右折返。对原版继续仿真400 tick（20秒），位置每16 tick重复，两个工地剩余工时始终为200和240。

工匠自动施工和手动移动使用不同的目标筛选：自动施工允许选择城外工地，手动移动却复用了闲置避险的城内限制。它因此只能选择墙内最接近命令目标的格子；到达后又持续朝格心移动，8 tick的动作保持导致反复越过格心。该限制始于提交 `90c66914`（2026-09-08），不是此次骑兵A*引入的问题。

另一个到场边界问题：工位格心已在施工半径内、工匠实际位置尚在半径外时，旧逻辑会直接排除当前格，可能找不到可用工位。

## 修改范围

- 手动目的地允许在城外；闲置避险仍优先城内。普通命令仍禁止安全工匠穿过威胁区，强制施工保持原有语义。
- 允许在当前格完成最后一小段施工接近，进入实际施工半径后停下。
- 格内接近逐tick选择能缩短距离的一步，无法继续靠近就停下，避免反复越过格心。复用已序列化的导航状态，无新增路径算法或全图逐tick搜索。

## 验证

- 缩小复现场景保留偏置城门、相邻兵营和塔、真实工匠速度0.08与施工半径1.6，以8 tick决策测试。旧版手动出城和格内工位两项失败；修复后通过，自动施工、不可达目标停稳也通过。
- 同一真实快照在修复版约1.8秒后通过城门；继续1600 tick后，原来的两个城外工地均完成。只使用存档副本，未更改玩家原局。
- 新基础存档v30（战术v31、宏观v32），World/20、Stats/15不变。仅v27纯脚本存档可通过完整快照迁移，必须通过平台、快照校验和世界状态哈希校验。迁移后及其后续存档均禁用旧操作日志回放；快照损坏明确拒绝恢复。新开局仍支持操作日志恢复，v28/v29旧模型局不迁移。
- Release构建后，`rts_tests '[workerpath]'` 4例26断言通过；`rts_tests '[script],[save]'` 58例6048断言通过，包含工匠安全/强制施工、任务认领、其他兵种脚本、快照续玩和操作日志恢复。

未据此推断长期配平或所有寻路问题已经解决；本修复针对目的地约束和施工到场振荡。

## 扩建和前哨仍需调整

当前工匠的“城内”只是所有存活墙门的坐标包围矩形，不代表闭合围墙、敌人可达性或友军保护。多个据点会扩大这个矩形；墙内侧施工偏好、无任务避险仍使用它。建设和战斗驻守已允许城外部署，但工匠的整体行为尚未形成对多据点的合理支持。

后续应分别评估：按安全可达路径选择工地、依据附近实际威胁和掩护避险、允许安全前哨附近待命。主堡垒可作为无明确任务时的默认位置，不应作为所有工匠行动的硬边界。自动建设AI中基于初始城圈的规划还需独立检查，不能将其与玩家手动建造限制混为一谈。本PR未擅自实施这次整体行为调整。
