# 攻方 RL 目标与评价体系全局审计

日期：2026-09-10。范围：攻方战术 PPO、原生单波环境、冻结评估，以及当前游戏候选分支的连续波次规则。性质：代码审计与奖励算术核验，不是新一轮训练结果或已定修改方案。

审计版本：训练源码为 `codex/rl-value-scale-pilot` 的 `0e925a64c30d49ebb693039dfb45d34bacf94c5e`；游戏候选为 `codex/balance-scouted-direction` 的 `8393f262569615105d8ab0692ca117e547c3c7a4`。下文源码路径及行号以这两个版本为准。本文独立提交到 main，并不表示这些候选实现已经合入 main；服务器已有实验使用其运行目录固定的源码与原生模块，不能拿本地分支版本替代实验身份。

## 结论

当前系统能衡量部分单波破坏行为，现有评估不足以证明连续波次攻方的实际贡献。审计覆盖目标、记账、时间尺度、信用分配、观测动作和筛选标准；这些环节不能一概定为缺陷。应先明确评价依据，再用对照实验决定是否调整奖励，不先承诺任何兵种加多少分。

本文按证据区分三类结论：**实现事实与范围限制**（例如字段含义、单波重置、未记录的指标）；**待验证的行为风险**（例如牺牲贡献是否被低估）；**参数标定问题**（例如 gamma=0.99 是否匹配战斗时长）。实现事实不自动证明行为退化，参数尚未标定也不代表机制错误。

“敌我使用同一价值定义”值得检验，但不等于敌我必须同价：守军花金币补充，普通攻方按波次预算生成，不死鸟有跨波次缺席代价。血量不能直接替代这些代价，金币也不是双方通用货币。

## 1. 实际在优化什么

`train/ppo.py:70` 的默认 economic 模式每次转移支付：

```
0.002 × 对单位实际伤害 + 0.004 × 对建筑实际伤害
+ 0.05 × 敌方单位击杀数 + 1 × 建筑基础石木造价
+ 3 × 非战斗单位击杀数 − 0.001 × 己方阵亡单位满血值
+ 2000 × 本次摧毁 Keep + 距离势函数差分
```

伤害按实际扣血记录，不包含超杀；胜利在重置前计入。victory 对照模式排除全部经济项。当前 anchor 实验使用默认 economic 模式。

这里必须纠正两点：

- `scouts_killed` 实际按 `!is_combat()` 累计，工匠也获得额外 3 分。不能说工匠完全没有额外奖励；字段名与语义不一致，使报告容易误导。
- 采集由 Quarry/Lumber/Mine 建筑自动产出，游戏没有独立采集兵。工匠负责施工维修，不能把工匠死亡直接解释为停止采矿。

证据：`rts_core/src/mechanics.cpp:401`、`:1125`，`train/learning.py:6`。

## 2. 已确认的计价方式与尚未表达的价值

以下为当前数值表的一级单位，从满血击杀、没有恢复，未折扣且不含距离奖励的算术结果；不是战斗实测或推荐价格。

| 守方对象 | 基础招募金币 | 击杀及全额伤害奖励 |
|---|---:|---:|
| Archer | 60 | 0.53 |
| Spear | 70 | 0.77 |
| Ranger | 90 | 0.69 |
| Scout | 25 | 3.25 |
| Mason | 40 | 3.29 |

昂贵单位不一定得分高，工匠加分也来自“非战斗单位”归类，而非维修停工的测量。这个表证明价值依据不同，不能单凭它断言具体排序一定错误：最后一名工匠、闲置工匠、破口处枪卫的边际价值本就不同。

一级不死鸟阵亡扣 0.19，攻城锤扣 0.65。此差异来自血量，不表示前者损失较轻。全局提高阵亡惩罚也有风险：破墙单位牺牲可能是合理交换。

建筑奖励只读取基础石木造价，不计等级、累计升级投入、资源点产出倍率、停产时间和施工维修时间。塔为 110，防空为 120，金矿为 90，伐木场/采石场为 70。经济建筑已有摧毁奖励，但不能据此认为经济打击被完整计价。

资源价值不应仅机械求和：缺石、缺木、缺金币的局面不同；敌人为防空花钱后仍持有防空建筑，不能把这笔支出全当成“被摧毁的资源”。威胁是与位置、克制、队友和后续战斗有关的情境价值，不能用固定血量×输出表直接替代。

## 3. 折扣机制合理，时间尺度参数有待验证

当前每次决策推进 6 tick，即 0.3 秒，gamma=0.99。折扣用于从某个决策时刻评价未来收益，不会扣减收益发生时记录的即时奖励。若时刻 1 获得奖励 1，从时刻 0 提前一步评价它的折扣值是 0.99；到时刻 1，这笔实际奖励仍是 1。摧毁 Keep 时实际记入的胜利奖励始终是 +2000。

采用“当下奖励 + gamma × 下一状态价值”的记号，回报为 `G_t = r_t + gamma × G_(t+1)`。各决策时刻都有自己的评价起点，并非所有奖励永远相对开局折扣。当前参数下，从同一评价起点看，未来奖励的折扣权重约每 20.69 秒减半。

| 从固定评价起点到胜利的延迟 | +2000 对该起点的折扣贡献（非实际到账奖励） |
|---|---:|
| 30 秒 | 732.06 |
| 60 秒 | 267.96 |
| 120 秒 | 35.90 |
| 140.1 秒 | 18.31 |
| 180 秒 | 4.81 |
| 240 秒 | 0.64 |

计算为 `2000 × 0.99^(秒数/0.3)`，用于解释时间尺度，实际转移索引可差一次折扣。它不是模型价值预测或实际到账奖励。例如 120 秒对应的 35.90，仅表示这笔胜利奖励对 120 秒前决策的折扣贡献；不表示胜利只发 35.90 分。

这些算术结果本身不能证明 gamma=0.99 不合理、导致短视或造成训练失败，也不能证明延长时限或调整胜利奖励一定无效。待验证的问题是：在本项目的战斗时长和价值估计条件下，当前参数是否低估早期准备行动的远期贡献。应在保持其他条件一致的对照中，比较早期破墙、掩护与后续突破表现，再决定是否调整 gamma。时间上限改变的是对局边界，折扣改变的是未来收益权重，二者应分别检验。

训练日志 `ep_ret` 累加未折扣奖励，优化目标使用折扣回报，两者用途不同，这种区别本身不是实现错误，报告应注明口径。距离势函数有终止归零及编队死亡边界修正，不能把中间出现的距离正奖励直接认定为刷分漏洞。GAE/价值估计仍可能影响学习，但需独立验证。

## 4. 团队协作的信用分配

所有有效编队收到同一时刻的团队奖励；`train/rollout.py:36` 按编队身份接续回报，编队全灭便停止接续，不会错误接到压缩后的另一个编队。

这解决身份串线，同时限定了直接信用分配的范围：先牺牲的攻城锤不能通过这段直接回报链收到队友稍后攻堡的奖励。破墙的即时奖励仍存在，共享网络也可能间接学到协作，不能声称“完全学不到牺牲”。这一边界是否实际妨碍合理牺牲，需要实验；调整兵种损失系数不会改变接续规则，但仍可能改变策略，不能未经比较就断言它无效。

验证应包含牺牲破口、掩护撤退、击杀防空后队友突破，以及全灭后在途弹丸完成击杀。先证明哪些贡献遗漏，再比较团队价值接续等方案；不得恢复已经修复的编队身份串线。

## 5. 模型是否看得见、选得到目标

`rts_core/include/rts/obs.hpp` 的局部通道包含敌方密度、血量比例和等级，但没有敌方兵种类别；非墙建筑主要压缩为一个血量通道，没有塔/防空/经济建筑类别。自身兵种 one-hot 不能补足敌方类别。全局仅有波数与空军存活比例，没有剩余时间、资源点收益或不死鸟重生等待状态。

所以不能假设“把高威胁敌人加分，策略就能识别高威胁敌人”。动作掩码、局势和运动可能提供间接线索，但没有消除这种信息缺失。

动作只有八方向移动、停止、最近敌人、最低绝对血量敌人、最近非墙建筑及墙门攻击。没有直接按威胁/经济价值点选目标，策略可以移动改变目标，但可控性有限。当前实验方向目标固定 Keep；经济目标模式存在，却未在本轮启用。训练没有显式撤退结算或跨波不死鸟身份机制。

还需补一个独立可见性测试：原生 `pick_target()` 枚举目标时未见迷雾过滤，而观测层有过滤。检查隐藏单位能否改变合法动作、目标或攻击结果；目前仅列为风险，不宣称已经证实信息泄漏。

## 6. 训练与游戏目标的差异

单波训练是合理的战术子任务，不应被直接等同于整个游戏。当前训练固定九编队，轮换地图、等级和入口；不包含攻方编成选择、跨波侦查记忆、动态预算及城市长期状态。

原生 BatchedEnv 以 Keep 摧毁、攻方全灭（考虑在途弹丸）或时间上限结束，再生成新城市。当前游戏候选 `DemoBattle` 则保留城市状态并生成下一波，还有不死鸟撤离、存活记录及阵亡后的重生等待。

因此“只剩不死鸟”在训练中可能拖到超时，在游戏中还受撤退规则控制。既不能把它认定为无价值，也不能拿训练里持续盘旋的全部击杀假定为游戏里可兑现的收益。

延长单波时间会同时增加攻方攻击机会和守方收入、补兵、施工时间。时间对照测的是这套完整规则的联合效果，不能归因为单一方面。

历史诊断边界：576 局时限对照与四个代表局详细复现是两种证据；不能把四局均为不死鸟推广到全部 78 个长时限超时局。本次不新增对局，服务器状态刷新因 SSH 通道超时未成功，旧实验数不冒充当前进度。

## 7. 评估与采用规则的缺口

`train/evaluate.py` 保存逐局 tally，主摘要偏重胜率、建筑伤害及建筑基础价值。`train/anchor_pilot.py` 的采用门槛要求逐案例胜率与建筑价值不退步，未将守军价值交换、不死鸟保存、经济恢复时间或后续突破纳入。

这可以筛选旧单波目标下的候选，不能证明连续波次战术更好。单独改成“总奖励最高者获胜”也不正确，那会让新奖励评价自己。

固定演示地图适合当前展示目标，但同图反复调参后的结果只支持这些图上的表现；匹配种子的配对局有助于比较，并非全部独立战术样本。训练窗口胜率、冻结胜率、完整游戏表现需要继续分开。

## 8. 全局验证方案与优先级

**优先级一：补齐可审计战果与目标定义。** 记录目标类型、等级、实际伤害、阵亡/撤退身份、资源及升级损失、经济建筑停产与恢复、不死鸟缺席波数，并把原始事实和奖励计算分离。保留各资源分量，不先强行兑换成一个总价。记账覆盖直击、弹丸、溅射、撤离与重建，避免重复计数。

**优先级二：检验信息与团队信用。** 用兵种不同但原观测相同的成对局势验证信息缺失；检验可见性、目标可达性、牺牲后贡献和剩余时间。只有确认必要后才改观测/动作契约，不直接扩大网络或动作集。

**优先级三：建立不依赖新奖励的实战判据。** 在既定演示地图上比较同样地图/初始城市/波次/预算/对手条件的冻结策略。记录最终攻堡、攻堡波数与用时、守军与建筑实际损失、资源收支及恢复时间、不死鸟出勤。达到观察上限的局面单列，不能假装最终失败或胜利。

**优先级四：小规模消融后再训练。** 分别比较旧奖励、统一基础价值的候选、折扣参数候选，以及有证据支持的团队信用候选；这些都是待评估方案，不预设必须采用。不要同时改全部参数后无法归因。使用同一初始模型，保存独立配置与奖励版本。候选权重必须能通过下列成对场景，再进入固定地图对照：

| 场景 | 要检验的判断 |
|---|---|
| 可立即攻堡 vs 延迟刷击杀 | 攻堡的主导地位在折扣后仍成立 |
| 击杀守军并撤退 vs 空转存活 | 有实际消耗应优于没有战果，是否兑现看后续 |
| 不死鸟换掉关键防空/工匠 vs 无意义阵亡 | 风险与收益都需计入，不能一律惜命 |
| 攻城锤牺牲开口 vs 保存却没有推进 | 团队后续收益能否回传 |
| 摧毁高产资源点 vs 未解禁资源点 | 不能只按建筑名称支付相同战略溢价 |
| 杀最后一名工匠 vs 杀闲置冗余工匠 | 情境价值是否值得复杂化，先测实际差异 |
| 反复伤害被维修建筑 vs 真正摧毁 | 维修资源消耗有效，但不可重复夸大同一损失 |
| 同等战术改变决策间隔或时限 | 排名变化是否来自时间计量失配 |
