## 奖励与训练更新

一个编队阵亡时，它的 GAE 链终止，但原先共享的势函数奖励仍保留其他存活编队的下一状态势能。其折扣回报因此多出一个与阵亡时刻有关的边界项，不再只是固定的初始势能偏移。四局真实轨迹中记录到 14 次这样的提前终止；其中一例残留项为 −0.2638448973。

现在为每个编队定义终止状态势能为零：阵亡且世界尚未结束时，从该编队的最后一步扣除 `gamma × 加权下一状态势能`；普通任务奖励保持原样，存活编队在 rollout 边界继续 bootstrap。终局、阵亡、行压缩和存活跨 rollout 的测试均覆盖。这是公式正确性修复，不能仅凭它断言所有训练退化都已解决。

另加两个显式选项：

- `--value-features detached`：价值损失只更新价值输出层，避免未训练好的价值头直接改动策略共享特征。它不是完整的 PPG 算法。
- `--reference-coef 1`：对已初始化的策略加入 `KL(冻结参考策略 || 当前策略)` 约束。参考模型随完整检查点一起保存；删除原始初始化文件后仍能恢复。新实验必须明确提供初始化权重，不能把随机网络悄悄当作可靠参考。

两个选项默认关闭。加入选项、尚未修改奖励公式时，与 v2 学习器做了一次真实 1,024 步更新对照，12 个模型张量逐一完全相等。之后的奖励边界修正会有意改变训练结果，并提升学习器合约版本。

参考动机：[策略与价值特征相互干扰的 PPG 论文](https://proceedings.mlr.press/v139/cobbe21a/cobbe21a.pdf)、[示范策略正则化研究](https://deepmind.google/research/publications/41182/)。这里采用的具体损失和默认参数仍需由本项目实验验证。

## 多地图、混兵、等级

`--map-pool` 接受有序的逗号分隔地图路径。地图由世界种子对池大小取模选择；守方陪练使用同一规则，在每次换局时重新绑定正确地图。测试将混合批次与逐图独立运行的观测逐项对比，并覆盖同一槽位换成另一张地图。

`--roster mixed` 使用 3 队亡灵步兵、2 队亡灵法师、2 队鬼域骑士、1 队攻城锤、1 队不死鸟。每队人数直接读取游戏定义；幽影窥使的侦查仍由脚本负责。`--levels 1,4,8,16` 控制初始等级，单位满血与等级缩放一致。地图、入口、等级按交叉组合遍历，避免相同取模把一张地图永远锁在某个入口或等级。

```bash
python train/demonstrations.py collect --out-dir runs/mixed/data \
  --map-pool game/data/maps/pool/gen_01001000.json,game/data/maps/pool/gen_01004000.json \
  --roster mixed --levels 1,4,8,16 --teacher flow_breach
python train/demonstrations.py fit --data runs/mixed/data/demonstrations.npz \
  --run-dir runs/mixed/fit --epochs 16
python train/ppo.py --run-dir runs/mixed/ppo --init-weights runs/mixed/fit/policy.pt \
  --map-pool game/data/maps/pool/gen_01001000.json,game/data/maps/pool/gen_01004000.json \
  --roster mixed --levels 1,4,8,16 --curriculum 1 \
  --value-features detached --reference-coef 1 --total-steps 32768
```

评估逐图进行，不把失败地图藏在一个平均数里。跨图复测使用独立的 `policy.pt`，显式指定地图、兵种、等级、守方与时限；完整检查点仍严格校验原训练合约。

## 导出与实际游戏推理

普通构建默认不引入 ONNX Runtime。可选 CPU 推理使用官方 1.29.0 SDK；Windows/Linux x64 自动下载均锁定 SHA256，也可用 `RTS_ONNX_ROOT` 指定已有 SDK。发布时保留随可执行文件复制的运行库与许可文件。

```bash
cmake -S . -B build-rl -DRTS_BUILD_RENDER=ON -DRTS_WITH_ONNX=ON
cmake --build build-rl --config Release
# 导出环境另需 torch、onnx、onnxruntime，以及对应版本的 rts_native。
python train/export_policy.py --checkpoint runs/attacker/policy.pt \
  --output runs/export/attacker.onnx --probe build-rl/tools/policy_probe/Release/policy_probe.exe \
  --unit-types Ghoul --min-level 1 --max-level 1
build-rl/render/Release/rts_render.exe --rl-policy runs/export/attacker.onnx
```

示例是 Windows 多配置构建路径；Linux 单配置可执行文件没有 `Release/` 和 `.exe`。声明的兵种与等级必须来自实际训练及评估覆盖，不能仅为启用更多单位而扩大范围。

导出器使用真实冻结策略轨迹抽样，分别验证 1、9、32 个 agent 的 PyTorch/ONNX 输出和合法动作，再调用编译后的 C++ 程序复核。首个已验证模型抽取 271 步中的 54 个观测，最大 logit 误差约 7.63×10⁻⁶，动作完全一致。32 agent 的 C++ 推理均值约 1.83 ms；这只计模型前向，不含方向场与观测打包，也不是完整帧耗时。

游戏显式加载 `--rl-policy` 后显示 `RL: N squads`。只有模型声明支持的编队由网络控制，其余保留脚本。模型输入来自攻方迷雾视角，观测目标、归一化、13 动作掩码、编队队长观测与广播规则匹配当前训练接口，决策间隔来自模型元数据。首波实际截图确认 6 支编队在使用模型。

这里有一个需要继续评估的行为边界：训练接口将队长动作广播给成员；默认游戏脚本则让成员分别采样方向场。实验性模型模式明确采用前者，不在接入时偷偷改成另一套执行规则。未来若调整这个编队契约，必须同时更新训练和运行端并重新验证，不能直接复用旧成绩。

存档记录模型内容标识。读取 RL 对局必须提供同一个模型；完整快照与操作日志回放的后续状态哈希均已验证一致。普通对局仍保存为 v3，RL 对局使用 v4，让旧程序明确拒绝它，避免用脚本静默接替。默认 `play.bat` 仍进入正式游戏；当前模型尚未作为完整攻方 AI 自动启用。

显式加载 RL 模型时，默认将对局与日记保存到用户存档目录的 `rl/<模型内容标识>`
子目录，避免实验覆盖普通玩家进度。不同模型各自保存；相同内容的模型移动位置后
仍使用原目录。显式提供 `--save-dir` 时遵循调用者指定目录。

## 可选的守方准备阶段

它缩小了开局差距，但还不是从完整多波存档采样：目前仍为固定混兵、一个入口、

## 攻方宏观目标与战术模型的连接

新版 `tactical-policy-2` 明确要求 `rts.goal_semantics=macro-flow-v1`。运行时按编队的
宏观目标，将现有观测中的流场方向指向堡垒或已知经济目标；不增加观测维度，也不新增全图资源情报。
流场缓存包含目标组，队员继续跟随队长的模型动作；经济目标为空时退回堡垒。
已有 `tactical-policy-1` 始终保留朝堡垒的观测语义，旧试玩包和已训练模型没有被重新标记。

`tools/make_goal_policy_fixture.py` 生成两个小型合成模型，仅根据当前位置流场方向选择移动。
ONNX 开启构建的 `[rlgoals],[rlpolicy]` 共 235 条断言通过，覆盖目标方向切换、两个同兵种编队
同时执行相反目标、队员广播、目标交换、空目标回退、非法目标拒绝以及原有模型加载和保存回归。
原测试将两个目标均放在部队西侧，首步相同；改用东西相反的目标后才形成有效的方向区分测试。
这些结果只证明运行时接线，不能证明学习模型已经会袭击资源点。

批量环境现提供原生 `BatchedEnvInit::goal_hook`，每次观测按环境获取已知经济目标与编队目标组，
入口仅接收该侧 `WorldView` 和队长列表，不回调 Python。未提供钩子或经济目标为空时保留堡垒流场。
同兵种同等级的不同目标不共用流场；非法目标在工作线程中被捕获并传回调用方。
默认构建 `[batchenv]` 的 29 个用例、930 条断言通过，新目标测试验证线程一致、目标分流、
非方向通道不变、空目标回退、重置以及无效输入。旧版绑定产物保留，尚未覆盖新原生源码。
该入口只改变观测；Python 训练尚未开启经济目标，旧 `progress` 仍表示靠近堡垒，不能当作经济任务奖励。
后续必须补齐采样、目标条件奖励、训练和冻结评估，才能导出、交付真正的新版学习模型。

原生绑定现可显式选择 `tactical_goals="known-economy"`（默认 `keep`），复用
`game::known_economy_training_goals` 按攻方侦查记忆选取采集建筑；没有已知经济建筑时朝堡垒前进。
当前采样将所有编队分配到已知经济目标，尚未实现宏观学习器的逐队分配。
`[traininggoals],[batchgoals]` 的 25 条断言通过：覆盖未知建筑不泄露、空点/错误建筑排除、
已知建筑保留记忆、视野外摧毁不偷改记忆、重新看见空地后撤销目标，以及批量目标隔离。
独立 `build-goal-training` 已成功编译并从 Python 读取两个环境的 18 个编队观测，原生指纹为
`3646edee3e9d1a04a117fd35093663ca05b442936f6f1892bbb4f8f28b649c43`。
尚未将该选项加入 PPO 配置；必须先将势能与分配目标对齐，再开启此模式的训练，避免堡垒距离势能误导经济任务。

稳定性修复现已接入：`train/stable_kl.py` 直接使用共享合法动作支持集上的归一化对数概率计算
KL(reference || policy)，不以浮点概率舍入为零判断数学上的零概率；非法动作严格贡献零。
五项测试验证普通输入与原库的值/梯度一致、极端分布有限值及解析梯度、非法动作含 inf/NaN、
单合法动作、半精度累加与非法输入拒绝；两项真实 PPO 参考模型冻结/恢复回归通过。
新 helper 纳入训练源码指纹，并加入可选 PyTorch CTest 测试集。

但原始非有限损失的具体 minibatch 没有保存，仍不能据此追认唯一根因。

## 固定袭扰分队训练模式

新增显式 `--tactical-goals split-economy`：每局创建时从己方食尸鬼/重骑编队按顺序取四分之一
（存在合格队时至少一队），保存该队全部成员句柄。队长阵亡由队友继承，整队阵亡不会临时从
主攻队补招；攻城锤、幽影和不死鸟不被分派到经济目标集。每个批量环境独立持有分配，创建或
重置世界时重新初始化，读取观测时不修改它。资源建筑仍只能来自迷雾记忆；没有已知目标时回退堡垒。

它缩小了旧 known-economy“全员转经济目标”的分布差异，但**尚非完整实战宏观模拟**：
固定采用默认 25% 分派比例，目标来自当局普通部队视野更新，未实现窥使跨波情报时序、
可学习的编成/入口/袭扰比例。旧模式保留，旧原生模块与检查点不覆盖。新模块为
`build-split-training/bindings/Release`。导出检查使用独立的
`build-split-export/bindings/Release`，不重建或覆盖正在训练的模块。

原生目标/批量环境回归 956 条断言通过；35 项 PyTorch 运行时回归通过，局间恢复测试现覆盖
三种目标模式。[同权重对照计划](rl-results/2026-09-09-split-goals-plan.json)固定四图、四级、
种子 1 的八局，比较 known-economy 与 split-economy；该轮只观察目标分配，不执行优化器更新。

[冻结模型对照结果](rl-results/2026-09-09-split-goals-comparison.json)核验计划输入 SHA、同一模型、
除目标模式外相同配置/合同，以及逐局地图、种子、等级、入口配对。两种模式都在 8/8 局观察到
实际经济分配。known→split 的经济编队观测累计 11718→1481、总活编队观测 18555→17896，
胜局 4→3/8、建筑价值 5650→3135、自损 27879→31507。它证明分工改变确实发生，
也表明直接切换旧模型没有带来效果提升；不能将接口更接近实战解释为策略变强。
下一步需在新分工下训练并保留同分工的旧权重基线，不能跨目标模式比较后把环境改变算成学习收益。

按[训练计划](rl-results/2026-09-09-split-training-plan.json)已启动 65536 环境决策训练，
最终只比较 update128，不以开发对照反复挑选中间检查点。[旧模型基线](rl-results/2026-09-09-split-training-baseline.json)
完成四图、四档各八局：1/4/8/16 级分别为 6/7/8/8 胜，建筑价值 2855/2975/2915/2630，
自损 17310/13389/8664/4228。高等级存在胜率天花板，必须连同战果、自损和逐局情况阅读。

所有编队都属于经济目标。原生测试包含不同编队数量的两个环境、主攻/经济混合、无目标回退，
目标与批量环境相关 45 条断言通过。[旧 known-economy 冻结模型回归](rl-results/2026-09-09-goal-row-export-regression.json)

## 三风格攻方训练 A/B（2026-09-09 接手后，Linux 服务器）

按[冻结计划](rl-results/2026-09-09-defender-profiles-ab-plan.json)在共用服务器（GCC 13.3 / Python 3.12 /
PyTorch 2.8，只用 CPU）跑完：control（原始脚本）与 profiles（`balanced,fortified,mobile` 轮换）
各两个训练种子，同一条 `pipeline.py`、同一预算（65,536 步 PPO），3 张留出图 × 4 档 × 2 种执行方式 ×
3 种评估风格各出一份报告，每组 72 份、共 288 份。归档与逐案例记录见
[结果](rl-results/2026-09-09-defender-profiles-ab.json)，比较脚本 `train/compare_profile_evaluations.py`
核过输入 SHA、两组配置除风格外逐项相同、每份报告只面对它标的那一种风格。

**预注册门槛未通过**（frozen_argmax，每种风格分别、两个种子同向）。胜局从未变差，
差的是种子 2 的建筑价值，幅度 2–4%：

| 风格 | 种子 1：胜局 / 价值 | 种子 2：胜局 / 价值 |
|---|---|---|
| balanced | 285→285 / 397→402 | 284→284 / 437→428 |
| fortified | 291→291 / 374→378 | 283→291 / 409→394 |
| mobile | 285→292 / 395→400 | 284→284 / 435→426 |

（每格分母 384 = 3 图 × 4 档 × 32 局。）144 对案例里 45 对有退步，全部列在归档里。

**但这个结果是「结构上为零」，不是「风格轮换没用」。** 三条证据：

1. 两组的模仿初值逐字节相同（示范采集刻意对原始脚本），而 PPO 之后权重平均只动了 7e-5
   （权重平均量级 1.7e-2，即 0.4%）；训练中熵 0.011→0.007、`approx_kl` 峰值 ≤ 2.5e-3、
   裁剪比例 < 1%。
2. 拿模仿初值本身去评：留出图 `01007000` 一级对 balanced，模仿初值 24/32、两组 PPO 后
   各 24/32，**32/32 局逐局一致**；分歧最大的案例 `01008000` 四级对 mobile，模仿初值 19/32、
   profiles 19/32（32/32 一致）、control 12/32（25/32 一致）——PPO 动了的那几局是变差的。
3. 两个配方探针（同一份模仿初值、同种子、同预算，只改学习器）：`reference_coef` 1→0 后策略
   真的动了（熵 →0.134、裁剪比例 7.9%），但两个案例分别 16/32、13/32，都低于模仿初值；
   再加熵系数 0.05 则两个案例都 0/32。

⇒ 在现行配方（近确定性的模仿初值 + `reference_coef 1`）和这个预算下，PPO 阶段几乎是空转，
两组比的是同一个模仿老师；放开参考项后 PPO 会动，但动的方向在 65,536 步内是变差。
**风格轮换有没有用，要等学习器能在自己的初值上改进之后才问得出来。** 这也和前面几轮
「候选单波复测通过、真实部署仍退步」的记录一致——那些候选与它们的初值之间差别本来就小。

下一步是学习器问题，不是风格问题：先在 control 组上做 `reference_coef 0` 的预算扫描
（65,536 → 262,144 → 1M），门槛是留出图上超过模仿初值本身；过了再重跑风格 A/B。
本节不宣称风格轮换在更大预算或其它配方下的结论，也没有真实多波对局与部署验证。
