# 瞭望塔密林探测与攻击暴露：设计提案

初稿：2026-10-12；修订：2026-11-05。状态：待评审，尚未实现或验证配平。本文只完善设计与验收约定，不修改游戏代码、数值表或试玩程序。现状核对基于 #208 的 `690a5aff`；下文“建议”均不代表已经生效。

## 目标与现状

让瞭望塔成为保护城防、前哨和施工现场的持续观察设施。密林提供隐蔽接近的机会，守方可以通过布置观察点、接近侦查和敌人出手获得情报；没有瞭望塔时，也应有发现、辨认和反击的机会。

当前瞭望塔视野12格、零伤害，价格20石/50木，建造工时160 tick，见[数值表](../game/data/stats_placeholder.json)。地面视线经过中间森林格时中断，端点不参与阻挡判定，因此林缘、紧邻格仍可能可见，见[视线规则](../rts_core/include/rts/visibility.hpp)。目前没有独立的近距发现或攻击暴露机制。

[核心选敌](../rts_core/src/mechanics.cpp)中，建筑和单位的攻击选敌均没有完整的可见性限制；部分脚本接敌、工匠风险计算也直接读取敌军，见[守军脚本](../game/src/defender_script.cpp)。不能把“画面看不见”解释为“敌人不会受到攻击”，也不能只修改箭塔就宣称情报边界全部闭合。

## 三种权限分别判断

| 权限 | 提供什么 | 不提供什么 |
|---|---|---|
| 普通地形视野 | 沿用现有可见格、探索和建筑记忆 | 不因特殊探测自动扩大 |
| 单位发现 | 当前确实发现的敌军身份及允许显示的信息 | 不点亮所在格，不揭露同格其他单位或隐藏建筑 |
| 攻击许可 | 按当前阶段的选敌、射程、对空/对地和弹道规则决定能否出手 | 发现不增加射程，也不自动获得穿墙攻击能力 |

单位实时可见的建议判定为：**普通视野可见，或被瞭望塔探测，或被近距发现，或处于攻击暴露期且有合法接收者**。后面三项均按目标单位计算，不能用 `FogLayer::mark_visible` 代替。

## 瞭望塔探测规则

- 完工瞭望塔在现有12格内发现敌军单位；只忽略森林遮挡，岩壁仍阻断。以建筑格心到单位连续位置的圆形距离计算，恰好12格算范围内；岩壁与夹角使用统一地形视线规则，不能由界面另画一套。
- 发现结果进入守方共享的**单位可见信息**，供画面、选中和目标提示使用，后续接敌迁移也读取这份结果。瞭望塔本身不造成伤害，也不增加其他建筑的射程。
- 林中探测不自动揭示整片林区及林后的建筑、施工或经济状态。正常视野与特殊单位探测分别计算，避免把敌人所在格标为全可见而泄露其他实体。
- 未完工时不探测；已完工塔在维修、升级期间继续探测。塔被毁后，在该tick下一次发布发现结果时移除其贡献；其他观察者仍能维持发现。重叠探测不叠加范围或延长隐身后的跟踪。
- 不按主城边界裁剪观察者：城外矿区和独立前哨同样有效。沿用静态建筑不得覆盖集结区的地图约束。

首版建议沿用12格及现有价格、工时，不额外设置升级探测加成。地形或塔的合法建造约束不变，不允许在密林里随意插塔；新用途下的投资价值仍待评估。

## 配套发现机制

| 机制 | 候选规则 | 边界 |
|---|---|---|
| 近距离发现 | 地面单位和完工建筑在 `min(2格, 自身vision)` 内发现敌军，忽略森林遮挡 | 岩壁仍遮挡；双方适用。木栅栏原有1格视野不会被扩大到2格 |
| 攻击暴露 | 合法攻击承诺时开始，前摇期间保持；实际出手再次刷新60 tick的尾随期限 | 对单位和建筑的有效攻击均适用；无合法目标的指令不触发 |
| 暴露接收 | 出手者在敌方合法观察者自身 `vision` 半径内，可越过森林遮挡被发现 | 使用观察半径，不是攻击射程；仍受岩壁遮挡，不全图广播 |

暴露规则适用于双方战斗单位；近距2格、尾随3秒均为候选参数。空中观察沿用现有能力，本提案不削减或额外扩大全图情报权限。

计时建议明确如下：

- 合法攻击承诺发生在tick `t`，记录截止 `t+60`；前摇进行中保持暴露，实际挥击/放弹再把截止延至出手tick加60。不等待造成伤害才暴露，命中或受伤本身不再次续期。
- 零前摇攻击也必须触发。目标在前摇中死亡或攻击被取消，不撤销已经产生的期限；没有实际出手就不获得第二次刷新。不能复用“攻击者和受击者混合”的交战事件直接揭露所有参与者。
- 连续有效出手刷新期限，仅保留攻击指令、冷却等待或空挥指令不会无限刷新。若前摇已结束，`now < 截止tick` 时仍有效，到截止tick失效。
- 例：tick 100承诺，tick 106放弹，且此后不再攻击，则在有接收者的情况下可见至tick 165；tick 166不再由这次攻击维持发现。若仍有普通视野、近距或瞭望塔贡献，则继续可见。

离开全部发现范围后，停止向本次新增呈现功能交付实时坐标、轮廓、血条及面板/镜头跟随；再次进入范围时重新判断。现有单位战斗追击不在首批收紧范围。特殊探测不新增敌军位置记忆系统，已交付的累计侦查报告也不冒充实时兵力。失视不会让已经发射的弹丸消失，既有锁定落点/追踪和碰撞规则保留；这不向玩家或AI额外公开隐藏目标位置。

## 共享情报与呈现

守方的合法观察者共享单位发现，城内与城外前哨一致。攻方普通编队只共享获准的战斗观察；窥使交付前的私人视野不能混入共享表。成功传输仍按现有规则交付一次性**建筑快照**，不变成全图实时单位情报，见[攻方情报约定](attacker-routing.md)。

瞭望塔发现窥使不等于直接击杀、取消传输或宣告侦查失败；是否完成观察、是否受攻击及传输成败仍由原系统结算。瞭望塔不代替斥候的移动探索和集结区报告，也不因探测到几名敌军就生成全军编成情报。

选中瞭望塔时显示圆形探测范围；岩壁导致的实际盲区应能辨认，不能只画圆就宣称圆内全可见。文案说明“可发现密林中的敌人；岩壁遮挡”。被发现单位在树冠下仍需有可辨认、可点击的轮廓或标记。画面、拾取、目标提示和统计必须消费仿真的同一份发现结果，不能由渲染器自行揭露。

## 与箭塔和攻方决策的关系

**首批增加发现能力，保持现有单位和建筑攻击许可。**收益先体现在玩家看得见、选得中和共享情报，不宣称箭塔因此获得新的开火资格。不能同时强化攻方利用密林、取消现有塔火，再用“视野更合理”代替难度验证。

后续先独立试验**箭塔Tower只对共享可见目标开始新攻击**，不要求每座塔亲眼看到。已经开始的前摇沿用承诺时落点，不因失视重瞄隐藏坐标；在途弹丸按原规则结算。防空Flak、单位选敌/掩码、主动接敌、工匠避险须分别列明迁移范围和回归，不能顺手一起收紧，也不能在尚未迁移时宣称所有AI都受完整情报约束。

瞭望塔适合覆盖林口、城墙外侧和远矿附近，玩家也能用接近观察和敌人出手获得发现。地图应保留开阔进攻路线，避免每面城墙都必须先买瞭望塔才能防守；不得新增针对边缘矿区的地面远征压力。

只有攻击许可调整并通过对照后，才试验攻方比较开阔/密林路线的行军时间、暴露时间、预计承伤及林口条件。已观察的瞭望塔按最近一次合法记录估计，隐藏升级、毁坏、新建不自动更新；未知覆盖仍是不确定性，不能偷读实时敌方探测表来算自己是否被看见。

当前塔火不因林区遮挡而停止，首批不能给“林中路线”虚构免伤收益。后续收紧攻击许可时同步更新承伤估算，覆盖进林、出林、开火暴露、已知瞭望塔和岩壁；单加“喜欢树林”权重不能代表战术完成。

## 实施与兼容边界

- 视野层提供带完整单位身份、接收方权限和当前tick的发现结果。先接入战场绘制、拾取、战斗提示及获准的观测统计；驻军接敌、工匠风险和核心攻击规则的迁移分别声明，首批保持它们现有决策。
- 不改写特殊探测格的普通迷雾或建筑记忆。核对 `BattleScene`、`BattleSignals`、`sighted_composition`、`census_visible_foes`、`obs_pack`、`macro_observation` 等按格筛单位的入口；未接入前不能宣称整条信息链已经一致。
- 暴露截止tick、前摇状态和完整单位身份进入确定性状态；死亡、重生与槽位复用不得继承旧暴露。可见结果可重算，恢复后仍须与原局一致。新增状态/规则时按契约升级世界哈希、快照和存档版本，旧档保留给对应旧程序。
- RL观测语义或攻击掩码若改变，即使维数不变，也要独立升级契约/指纹并重新评估。旧模型不靠改标签冒充适配，本提案不规定模型训练结果。
- 现有视野更新在tick末尾，后续可见性选敌必须明确读取哪一拍的结果，覆盖新出手、移动、塔毁和零前摇；发现期限以20Hz tick计，不依赖帧率或8tick脚本决策周期。画面与AI只能读取已发布结果，不为其调整仿真阶段顺序。

## 验证与实施顺序

先完成规则与信息权限验收，再做独立的攻击许可和配平试验。以下是**待实现的验收要求**，不是已通过结果。

| 场景 | 必须满足的结果 |
|---|---|
| 目标在12格、12±ε及斜向边缘 | 恰好半径内发现，半径外不发现；不使用方形或整格近似扩张范围 |
| 厚林后有敌军，观察线经过/不经过岩壁 | 瞭望塔只穿森林；岩壁及夹角按统一规则阻断；未被探测的盲区不能显示 |
| 无塔、近距2格；木栅栏仅1格视野 | 合法近距能发现，岩壁仍遮挡；木栅栏不凭空获得2格探测 |
| 无任何接收者时敌人出手 | 可以记录暴露期限，但对方得不到位置；进入合法范围时重新判断 |
| 零前摇、目标前摇中死亡、连续出手、攻击落空 | 时序符合上文；无目标指令不触发，命中不重复刷新 |
| 仅A由攻击暴露被发现，B与其同格且没有其他发现来源，附近有隐藏建筑C | 只交付A；B保持隐藏，普通迷雾与C的建筑记忆不变 |
| 目标离开全部范围、唯一塔被毁、暴露到期 | 没有其他发现来源时停止实时显示及面板/镜头跟随；既有战斗追击和弹丸按当前阶段规则处理 |
| 重叠瞭望塔、维修/升级、未完工塔 | 重叠不扩半径；修/升级不失效；工地不探测；摧毁一塔不清除其他来源 |
| 城外两个前哨、远矿、窥使发现/传输 | 不按主城裁剪；不新增远矿远征；发现窥使不直接判侦查失败 |
| 暴露单位死亡、重生、槽位复用；中途存档恢复 | 新身份不继承暴露；恢复和逐tick重放的发现结果/哈希一致 |
| 首批相同固定攻击和随机种子 | 新发现可以改变呈现，不能偷偷收紧单位或塔的既有攻击许可 |

配平采用三组：A原规则、B仅新增发现、C在B上限制Tower新选敌。先做固定行动的规则隔离，再做正常AI/玩家行为对照；固定地图、种子组、波次、总投入及运行配置，记录提交和配置指纹。新机制组不能免费多送瞭望塔；另比较同预算的观察/火力投资，评价机会成本。

分别报告前1—15波和中后期的首次发现至接敌窗口、首次暴露至可反击窗口、塔有效输出、守军/建筑损失、堡垒承伤、额外观察投入。重点核查无瞭望塔时是否存在可读的反制，以及林中单位是否长期不可交互。B组通过不代表C组难度合理，需玩家试玩复核后再决定是否启用。

性能在Release下测开局、多据点、密集林区及大量单位，记录每tick平均值、P95/P99和整帧预算占用；同一输入下对照简单完整扫描的结果。沿用[共享观察与完整扫描](scan-performance.md)的稳健方向，权限必须单独保留；既有几何查询基准不能充当新机制性能结果。先处理重复计算，只有整体预算实测不足才评估替代算法。

本次修订只完成代码口径核对、规则细化与验收设计，没有运行新机制、配平或性能实验。12格沿用现值，2格近距和3秒暴露待标定；攻方路线、林区生成布局及其他攻击许可仍按上述阶段分别评审。
